# Agent 运行规则

本工程运行时依赖、但原本只写在 rtx3080ti 用户级 `~/.claude/` 里的规则，写成与 harness 无关的形式，给没有这些用户级规则的 harness（如 rtx4070tis 上的 Codex、Antigravity/agy）用。rtx3080ti 上的 Claude Code 照旧读用户级规则；两边内容重叠或不一致时，Claude Code 以用户级规则为准。

这里只写规则；个人偏好（对话语言、回复长度等）放在各 harness 的用户级指令里。

## 状态页

每个工程一页，由所在机器总层的 `.status/status.txt` 渲染（不在本仓库）。只经 `~/.claude/status/status.py` 修改（`set`/`done`/`rm`/`order`/`list`，用法见脚本开头说明；它给每项盖时间并重新渲染），不手改数据文件。

- 分区：`decide`（待用户决定）、`know`（用户必须知道）、`now`（正在进行）、`queue`（全部待办，按优先级用 `order` 排序）、`done`。保持当前状态，不往上堆历史。
- id 在所有分区里唯一：对已有 id 执行 `set` 会把它移到新分区，所以同一工作的 `decide` 和 `now` 要用不同 id。
- 一项写清对话汇报里要说的：结论、意义、关键数据、偏离、遗留、文件和报告路径。可用多行 markdown（列表、`|` 表格、粗体、`code`）。
- `decide` 每项自成一体：背景、选项、建议，不写成"见某文档"。用户答复后删掉；用户说已读后删掉对应 `know`。
- 工作状态、决定、必须知道的事都放状态页；对话回复只答用户问的，或说明状态页改了什么。

## 推送

命令：`~/.claude/hooks/stop-notify/push.sh "<一行消息>"`，在本轮最终回复之前运行。不传标题时，脚本取会话标题，找不到时用目录名；Codex、Antigravity 下没有会话标题，就用目录名。

- 何时推送：本轮新增或改动了 `decide` 项；本轮请用户动手做某一步；不是用户消息触发的一轮（后台检查、任务结束）以结果、失败或新增 `know` 项结束。
- 消息写明哪项工作、需要用户做什么，例如"Code Spec Q3×5 完成，需你决定 1 项"。`know` 写"待你知悉"，只有 `decide` 才写"待你决定"。
- 推送经公共 ntfy.sh 服务器：消息里不放凭据、私有配置、文件内容或测量数据。

## 用户亲手操作

某一步需要用户动手（打开或编辑文件、批准 UAC、填写数值）时，先说清用户要做什么，取得明确同意后再开始。用户没注意到的等待永远不会结束。

## 后台长任务

模型运行、部署、长测试和轮询都按后台长任务处理，不靠会话存活：

1. 用 `setsid nohup <命令> > <日志> 2>&1 &` 分离启动，记下每个长驻进程的 pid。
2. 任务把进度写进 `.tmp/<工作>/` 下的进度文件；运行计划（`run-plan` skill）也放在这里，状态页 `now` 条目给出路径。
3. 任务存活期间至少每 20 分钟检查一次进程和进度文件，及时发现停滞。harness 有定时机制就用它；没有就在当前一轮里间隔检查。会话中断不影响任务，下一个会话从进度文件接续。
4. 某一步需要的进程在该步结束后（成功或失败）按 pid 停掉；汇报前列出仍存活的进程，确认没有遗留。
5. 用户叫停时立即停止任务，并确认租约、锁、进程都已释放。

不再需要的后台进程和临时文件及时清理；删除前按 AGENTS.md 硬约束 1「删除前核对」列清单核对。

## Codex CLI 定时任务

Codex CLI 需要未来待办提醒、到点唤醒或空闲时周期检查时，读 [Codex CLI 定时唤醒](codex-cli-scheduling.md)。定时器只调用 `codex queue` 投递到仍打开的现有会话，禁止用 `codex exec`／`codex resume` 重新启动会话；CLI 正常关闭时必须清理该会话的 timer。

## 独立审查

AGENTS.md 硬约束 1 的重要决策（冻结、默认参数改值、部署、改测量设计）要先取得独立意见：

- 另开一个只读会话，模型和推理强度都不低于 Main。Codex 下用 `codex exec --sandbox read-only`，模型和 `model_reasoning_effort` 不低于当前会话；Claude Code 下用 Agent 工具开新 agent；Antigravity 下用 `invoke_subagent` 工具（`TypeName: "research"`，在只读沙箱运行）。
- 交给审查方的是代码、数据和问题本身，不附 Main 的结论，避免被带偏。
- 审查会话只给意见，不改文件；Main 综合双方意见后执行，双方意见和结果写进该工作的报告。

## 额度

- 额度由总层计划决定（`~/.claude/docs/agents.md` Quota check），本工程不做额度判断。
- `rtx4070tis` 及其他主机没有额度预检脚本，不执行额度预检。它们仍须按硬约束完成 Strata key、租约、模型状态等运行前检查。
