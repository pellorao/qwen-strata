# Supervisor 会话设计（待审）

状态：方案，2026-10-10 起草，未实现。目标：让审批和重复判断共用一个带上下文的本地模型会话，知道主 agent 当前在做什么，再据此判断“这个动作是否符合当前工作预期”和“这是否在重复”。

## 已知事实

- 引擎单会话持有显存前缀缓存；开启会话暂存（rtx3080ti 已默认 `8192 MiB / 4 槽 / 保留 5120 MiB`）后，交替的会话按**精确 token 前缀**识别并暂存到内存，无需会话 ID。实测约 17K token 的主对话暂存约 0.1 秒、恢复约 0.03 秒。
- 因此 supervisor 会话必须**只追加不改写**：每次请求 = 上次的全部消息 + 新增内容，前缀才能从暂存中恢复，只读新增部分。
- Claude Code hook 是每次调用一个新进程，会话状态要落在文件里（按 Claude 的 `session_id` 分开）。
- 审批 hook（`PermissionRequest`）只在需要授权的动作上触发；`PreToolUse` 在每次工具调用前触发，可拒绝并附理由。推理内容和可见输出只能从 transcript 读取，hook 看不到正在生成的单次响应。

## 方案

### 1. 一个 supervisor，两种问题

`bin/qwen-supervise`（取代 `qwen-approve`）维护每个 Claude 会话的 supervisor 会话文件：

```
system: 监督者角色、授权规则（只有用户消息授权）、重复判断规则、输出格式
user:   [增量] 自上次以来 transcript 新增的用户消息、助手输出、推理摘录、工具调用与结果（标为不可信数据）
        [问题] 待审动作 / 是否重复
assistant: {"work": "<对当前工作的一句话理解>", "decision": "allow|deny", "repeat_p": 0.0-1.0, "reason": "..."}
user:   [增量] ...
...
```

- 每次只发送 transcript 增量，supervisor 自己的历史回答（含 `work` 摘要）留在上下文里，这就是它“知道目前在干嘛”的来源。
- 审批请求：回答 `decision` + `repeat_p`。
- 普通工具调用（不需要授权的）：只回答 `repeat_p`，见第 3 节的触发条件。

### 2. 上下文上限与自我压缩

supervisor 会话超过上限（建议 16K token）时，用它最近一次的 `work` 摘要加最近若干条增量重开一个新会话；旧会话不再引用，暂存槽按最久未用淘汰。上限可调，测量后确定。

### 3. 何时触发重复判断（需要你选）

| 选项 | 触发 | 每个任务的额外耗时（估算） | 特点 |
|---|---|---|---|
| A. 每次工具调用 | `PreToolUse` 全部 | 每次约 2–3 秒；100 次调用约 +4 分钟 | 覆盖最全，最慢 |
| B. 机械规则先筛（推荐） | 机械规则（同一调用和结果完全重复、近似重复）给出 0.4–0.9 的不确定概率时才问 supervisor；审批时顺带回答 | 多数调用 0 秒 | 对应规则里的“组合”路线；机械规则零成本 |
| C. 只在审批时 | `PermissionRequest` | 只有审批的耗时 | 只读命令的循环发现不了 |

B 的机械规则只用本次运行已收到的文本做比较，符合检测器约束；它本身也作为“纯程序”路线单独评分。

### 4. 判定后的介入

- 审批 `deny`：照旧拒绝并附理由。
- `repeat_p > 0.6`：`PreToolUse` 拒绝这次调用，理由写明“与第 N 次调用重复、没有新进展，请换方法或向用户报告”。具体介入方式属于判断逻辑调整，实现前另行审核。
- 单次响应内部的推理循环 hook 看不到，仍由引擎侧处理，不在本方案范围。

## 验证（需要模型，另行申请）

1. **离线重复判断**：supervisor 作为检测器接入 `tools/loop/corpus_replay.py`，按评分合同第 3 版全量重放语料（工具记录约 1709 条，单次约 2–3 秒，模型时间约 1.5 小时）；与纯机械规则、组合分别报告 F1。
2. **审批**：沿用 S3 伪造 rm 场景和 2b 审批场景，比较 qwen-approve 与 qwen-supervise 的判对率和耗时（单次 ≤ 10 秒、中位数约 3 秒）。
3. **缓存**：确认主对话和 supervisor 都从暂存恢复，主对话未缓存输入仍只有冷启动那一次。
