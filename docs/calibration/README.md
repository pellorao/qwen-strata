# 按主机和模型独立校准参数

本目录保存跨主机通用的调参方法；每台机器的参数证据、结论和待办放在各自文件中：

- [rtx3080ti](rtx3080ti.md)

详细历史和统计见[调优记录](../tuning.md)及各报告。某台机器或某个量化有收益，不表示另一台机器或另一个量化同样有收益；某值在测试中固定使用，也不证明它比其他值更好。每台机器只对唯一对外模型调参。

## 记录口径

次数指有效独立模型实例，每条件三次。资源任务每实例三个逻辑请求；采样专项使用完整 Commit Audit 任务，不能把评审次数当作三个短请求。主机旧证据保留原版本和方法，不冒充新版复验。

证据、候选、采用决定、默认及安装预置均以“主机标识＋模型标识”为键独立绑定。不能继承另一台机器的赢家；同机换量化也不能继承。代码同步、相同数值或同一模型系列都不替代验证。可变来源只在工程；安装目录只用于部署和回读。

## 每机执行方法

1. 核对当前主机和精确模型身份、GPU／CPU 拓扑／RAM、版本、模型／tokenizer／profile 校验、默认文件和服务状态。记录当前默认与实际运行覆盖值是否不同。
2. 筛选候选前搜索 Strata GitHub issues、讨论、PR 和官方说明，核对该具体 GPU 型号、版本、量化、CPU／RAM、上下文与测量口径。区分实测、建议与推测；缺少适用经验时明确说明。
3. 每条件三次、同一主机、同一模型独立对照，固定其他条件。CPU 亲和性之后才比较 worker；参数维度依次比较，不组合成矩阵。改变条件后不能拿旧版或其他硬件结果作严格控制组。
4. 使用[资源负载规则](../../benchmarks/resource-calibration-v1/protocol.md)的约 32K 三任务，每项核对完整 28 条 JSON；CPU 辅助额外使用[四记录短材料](../../benchmarks/resource-calibration-v1/cpu_share_workload.py)，完整模板必须包含基础启动提示。
5. 每个主机／模型组领取该机独占 key，API 启动、请求、停止和归还，保持 default/no-save。每逻辑短任务 150 秒累计工作限制；故障恢复沿用同项授权，真实配置失败必须保留。
6. 用原始内部 read／reused／generated 计量，统计工作时间及四项速度。API usage 只作诊断。分任务记录缓存、输入长度、输出长度、错误、实际参数、加载／停止、profile 前后 SHA 和必要不确定性。
7. 采集器在空闲时先验证实际运行与收尾。Windows 原生 SSH 启动的采集进程要脱离 SSH 任务。精确 CPU 专家分担数在当前 API serve 路径没有输出，保留未知；不能用其他指标补造。
8. 选择先满足完整正确，再比较工作时间、引擎速率、缓存容量和资源余量。spec-min-p 同时核对实际草稿接受与输出变化，不把输出更短全部归因于引擎更快。
9. 一个组闭合后立即交付结果、分析及下一组范围／预算，等待用户审核。采用值只在该机该模型获得决定后进入对应默认／预置，逐台回读并记录实际生效范围。

## 存放

- 每机调参事实写入 `docs/calibration/<host>.md`。
- 新报告写入 `reports/<host>/<版本或主题>/`。
- 当前待办只放该机本地状态页。

这套校准是新机初次采用或相关变化触发的独立工作，不是每次 Strata 更新的固定全量流程。每台机器只对本机唯一对外模型开展参数选择；不对外量化默认不测。完整 Reviewer 收益另行安排。
