# 测量规则附注

[测量规则](../.claude/rules/measurement.md)中只在复核或重做对应步骤时用到的依据和操作细节。

## Opus 参照速度探针

子 agent 会话记录的流式 usage 只有占位值（`output_tokens` 8），不能用来算速度。现行做法是用无头 `claude -p --model opus --output-format json`（或 `stream-json` 取逐事件时间）跑探针，它给出准确的输入、缓存、输出（含思考）token 和 `duration_api_ms`：输出速度 = output_tokens / 生成耗时。耗时含首 token 延迟，所以是下限，长输出时偏差很小，报告注明。输入处理时间分不出来时，模型直接输入速度记为未知。

## 分阶段判定的模拟依据

模拟实现是 `tools/tuning/staged_decision.py` 的 `simulate`。

- 两个条件（组内标准差 0.04）：真实差为 0 时误判约 6%、72% 提前判为等效，平均样本 8.4；真实差 0.06 时判出率约 88%。
- 多候选 c_final 按模拟标定，使全部候选真实相同时误淘汰任一候选的概率仍约 6%。
- 3 候选模拟（组内标准差 0.04 / 0.06，各 3000 次）：全部相同时平均 27 / 32 个实例，误淘汰约 6%，判等效 52% / 4%，其余到 11 个未判定；一个高 0.10 时 18 / 25 个实例判出（100% / 84%）；一个高 0.06 时判出 73% / 29%。组内标准差是耗时和判定率的主因。
