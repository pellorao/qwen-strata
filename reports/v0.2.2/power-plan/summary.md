# rtx3080ti 电源计划对照：平衡与高性能（2026-10-23）

## 结论

- 两种计划下 Strata 速度相差不到 1%，处在块间噪声的量级内。以高性能对平衡配对（B/A）：
  - 引擎输出：块级比中位数 0.996（−0.4%），在 1 个 SE 以内；6 对里有 2 对高性能更快。
  - 引擎输入：块级比中位数 0.997（−0.36%），约 2 个 SE，方向偏向平衡，没有实际意义。
- 两项都远低于事先定的 3% 判定线，所以**一直用平衡**，跑模型时也不切高性能，运行脚本不加切换逻辑。这保持现状，部署默认没有改。
- 适用范围：rtx3080ti（i9-13900 + RTX 3080 Ti，驱动 617.42）、IQ3_XXS、Strata 0.2.2（011c9e60，引擎 0.1.47）、当前部署默认参数，负载为单请求串行的 32K 合成三请求。以下情况没有覆盖：并发、100K 以上的长上下文、ARW 或 agent 长会话、CPU 长时间空闲后的短请求。
- 18/18 个正式请求全部正确。没有意外事件：单请求最低输出 110.3 tok/s，没有超时，没有重启。

## 方法

- 块顺序 ABBA BAAB ABBA，A 为平衡（381b4222-f694-41f0-9685-ff5bb260df2e），B 为高性能（8c5e7fda-e8bf-4a96-9a85-a6e23a8c635c）。共 12 块，每种条件 6 块、18 个正式请求；整个测量持有一个租约，用时 60 分钟。
- 每块的步骤：
  1. 用 `powercfg /setactive` 切换计划，再用 `getactivescheme` 核对；
  2. 静置 60 秒；
  3. 冷加载模型，核对 max_context 206584 和启动提示 SHA 1cae169a…；
  4. 预热一轮：同样三请求，加块编号前缀让缓存不命中，不计分；
  5. 跑正式三请求；
  6. 停止模型，从引擎日志计量。
- 负载：resource-calibration-v1 的三请求。参数为 temperature 0、top_k 20、effort high；引擎用部署默认值，没有 override。
- 切换授权：用户 2026-10-23 授权，只限本次测量脚本。脚本在 finally 里切回平衡；测完由 Main 独立查询，当前计划为平衡。

## 偏离与未验证

- 每块加了一轮不计分的预热，因此绝对值不能和历史资源维报告直接比较。
- 用临时驱动复用了 `tools/tuning/resource_calibration.py` 的函数，原因是它的 run 入口只接受改引擎参数或环境变量的条件。
- **没有核实 CPU 实际频率确实随计划变化**：Windows 上 `psutil.cpu_freq` 恒为基准频率，读不出实际频率；也没有读 PCIe ASPM 的链路状态。这两点只能从 GUID 确实切换过来推断。
- 测量期间 CPU 占用约 66%（23 个专家 worker），没测到轻负载时最低频率 5% 的影响。
- 两种计划下都有常规告警：VRAM 余量 144–276 MiB；`--pool-workers 15` 建议。平衡第 9 块出现过一次 `sw_thermal`（GPU 最高 77°C），这一块的速度没有异常。
