# v0.1.42 升级（rtx3080ti）

2026-10-11，用户授权安装（"允许今晚执行 python3 -m tools.ops.upgrade_release --host rtx3080ti 安装 Strata v0.1.42"），同时决定服务默认模型改为 IQ3_XXS 并在本机重新调参。

## 结论

- rtx3080ti 已升级到 Strata v0.1.42，**通过了短调用链检查**（S1，Q2_0）。检查经由实际使用的 `bin/qwen-agent` 入口，覆盖了 Claude Code 和 Codex。
- 本次只是短检查，不代表完整验收，也不继承 v0.1.41 的结论。上游说明 v0.1.42 的回答会略有变化，所以 v0.1.42 的结果不与 v0.1.41 直接比较。
- 默认模型已改为 IQ3_XXS，8 维调参已完成并部署，见[调参报告](iq3_xxs-tuning/)和[调参手册](../../docs/host-tuning.md#iq3_xxs)。
- Q2_0 只作 IQ3_XXS 的基线对比。同一冻结 Commit Audit 场景（各 3 次）的诊断结果如下：

  | 模型 | 得分 | 工作时间 | 解码速度 |
  |---|---|---|---|
  | Q2_0 | 0.773 | 11.6 分钟 | 117.6 tok/s |
  | IQ3_XXS（调参后） | 0.837 | 13.3 分钟 | 104.0 tok/s |

  IQ3_XXS 得分更高，Q2_0 更快。详见下文。
- rtx4070tis 仍离线，版本未变，恢复后需要同步。
- **已知风险**：上游 [#1622](https://github.com/Niko1221/Strata/issues/1622)（v0.1.41 生成循环）仍未关闭。本次短检查和 24 个完整 Commit Audit 实例中都没有出现循环。

## 发布说明核查

[官方发布](https://github.com/Niko1221/Strata/releases/tag/v0.1.42)，2026-10-10，标签提交 `61b3fb5dd3f1e8ec09cf7e4e05208bc6d3c46406`。未发布的 0.1.41.1 修复都已并入本版。

| 变化 | 对本机的影响 | 处理 |
|---|---|---|
| CUDA 默认开启专家尾部跳过（`STRATA_ROUTE_TAIL_SKIP=7`），上游实测解码 +13–16%，回答略变（KL 约 0.003–0.006） | 本机两个量化都适用：单 GPU，专家没有全部常驻 | 保持上游默认；需要逐字复现 v0.1.41 时，用 `STRATA_ROUTE_TAIL_SKIP=0` 加 `STRATA_PREFILL_CPU_SHARE=0` |
| i-quant 在不传 `--pcie-frac` 时按 CPU 实测设定 PCIe 分担（3060 + IQ3_XXS 上 +30%）；Q2_0 自带的包仍用固定份额 | 原 IQ3_XXS 模板写死 `--pcie-frac 0.00`，会挡住这项改进 | 第 1 维实测：不传时解码快 11.1%，已改为不传（[报告](iq3_xxs-tuning/pcie-frac/summary.md)） |
| CPU 辅助短输入在内存或 commit 不足时自动跳过 | 本机内存充足，没有跳过 | 第 6 维保持 auto（[报告](iq3_xxs-tuning/cpu-prefill-share/summary.md)）；上游 [#1729](https://github.com/Niko1221/Strata/issues/1729) 反映它在没有 AVX-512 的 CPU 上会拖慢解码，本机实测 auto 更快 |
| 取消请求后保留已恢复的会话缓存（#1620） | 有利于 Codex 中断后重试 | 未专门验证 |
| 工具集顺序稳定（#1624） | 有利于前缀缓存命中 | 未专门验证 |
| 思考预算接近 `max_tokens` 时提前收尾（#984） | 本机预算 8192，`max_tokens` 24576，不触发 | 无需处理 |
| 并行请求挂起、AMD、Intel、多卡、Pascal 等修复 | 与本机无关 | — |

上游与本机相关、尚未关闭的问题：#1622（循环）、#1729（CPU 辅助）。#1884（尾部跳过在专家几乎全部常驻时略慢）不适用于本机。

## 短检查 S1（Q2_0）

只有一个实例，每项跑一次，不取均值，也不算正式评分。每个阶段是一次独立的 `qwen-agent` 运行。C1 冷加载了模型，之后 3 个阶段都复用已加载的模型，因为前端会让模型保持加载，到空闲超时才停。

| 阶段 | 内容 | 结果 |
|---|---|---|
| C1 | Bash 写入随机标记（经 qwen-approve 放行）→ Read 读回 → Brave MCP 搜索发布页 | 通过：标记原样读回，URL 正确，Bash 和搜索两次审批都放行 |
| C2 | 同一会话 `/compact`（PreCompact hook 追加工程压缩提示） | 通过：20,668 → 2,545 token，27.7 秒 |
| C3 | 同一会话恢复，不用工具回忆标记和 URL | 通过：输出 JSON，两个值都正确，没有调用工具 |
| X1 | Codex 执行 `cat note.txt`，再用托管搜索找发布页 | 通过：命令输出正确，web_search 返回正确 URL |

| 阶段 | 总耗时（秒） | 入口请求 | 未缓存输入 | 已缓存输入 | 输出 | 引擎输入 token/s | 引擎输出 token/s |
|---|---:|---:|---:|---:|---:|---:|---:|
| C1（含冷加载） | 59.553 | 5 | 21274 | 37364 | 1200 | 744.5 | 114.2 |
| C2 | 28.285 | 1 | 2020 | 19871 | 2873 | 599.2 | 118.5 |
| C3 | 6.778 | 1 | 5912 | 13647 | 305 | 1922.0 | 100.5 |
| X1 | 21.972 | 2 | 13246 | 10681 | 380 | 852.2 | 116.3 |
| 合计 | 116.588 | 9 | 42452 | 81563 | 4758 | 839.5 | 115.9 |

- token 全部取自引擎日志，每个入口请求对应一个执行段。
- 与 v0.1.41 的短检查相比：引擎输出从 108.5 升到 115.9 token/s。但负载不同、样本只有一次，而且 v0.1.41 每个阶段都冷加载，不能当作版本对比。
- 观察：冒烟工作目录放在工程 `.tmp/` 下，Claude Code 因此加载了本工程的项目说明，回答用了中文和 Insight 格式。这不影响检查项，但以后的冒烟目录应放在工程目录之外，以免带入工程上下文。

## Q2_0 与 IQ3_XXS 的 Commit Audit 基线对比

条件相同：冻结 ARW Commit Audit 完整场景，各 3 次，Codex high，基础提示接入；评分用原版 `score-completed`，Main 逐条裁决。Q2_0 用安装默认参数（未调参），IQ3_XXS 用调参后的默认值。两组不是同一时间交错执行的，跨组比较的证据比组内比较弱。

| 模型 | 诊断得分 | 各次得分 | 平均工作分钟 | 输出 token | 引擎输出 tok/s | 草稿接受率 | 等效费用 $ |
|---|---:|---|---:|---:|---:|---:|---:|
| Q2_0 | 0.773 | 0.802 / 0.741 / 0.777 | 11.6 | 68846 | 117.6 | 79.1% | 0.086 |
| IQ3_XXS（spec-min-p 0.9） | 0.837 | 0.835 / 0.835 / 0.841 | 13.3 | 71893 | 104.0 | 92.4% | 0.086 |

- Q2_0 的 95 个裁决候选全部为同一缺陷（[91] 把 NFKC 遗漏标成"不确定"，按同类先例按语义匹配，类别不改）。
- 会话检查（独立 agent 逐实例完整读完）：instance-1、2 通过。instance-3 在报告最终写入之后执行了 `env | grep -i -E 'ARW|RUN_ID'`（环境身份查询，输出中有 runtime.json 路径、CODEX_HOME、运行标识，没有凭据），目的是按 Role 规则发中途通知；随后两次提权调用 `arw background-agent list_agents` 都失败，没有发出消息。这两次提权请求触发了 guardian 审查子线程（同一个 Q2_0 模型，两次都判 allow），带来约 26.9K 未缓存输入、约 2K 输出和约 50 秒墙钟，已计入该实例的引擎 token。报告在查询之前已经写定，输出也不含答案或评分材料。2026-10-12 按结果重判（用户确定，`.claude/rules/reviewer-suite.md` 会话检查）：样本有效，分数照常计入，标为"诊断分（环境查询 1 次）"，不乘 0.9，批次不判失败（原记"Q2_0 批次正式验收失败"，撤回）。IQ3_XXS 的 p090 批次同类查询按同一标准重判。分数不变。诱因是 Role 的 send_message 规则与运行环境不匹配，已列入 `docs/plan.md` 待办。
- IQ3_XXS 得分高 0.064，三次都高于 Q2_0 的最高一次；Q2_0 解码快约 13%，工作时间少约 13%。这与"IQ3_XXS 作默认"的决定一致。是否给某些任务改用 Q2_0，由用户决定。

## 回退

如需回退到 v0.1.41：

```
python3 -m tools.ops.upgrade_release --host rtx3080ti --rollback .tmp/maintenance-backups/release-backup-20261011-025022-954379 --output .tmp/strata-upgrade-current/out/rollback.json
```

之后还要把 `config/maintenance-baseline.json` 的版本改回 0.1.41 并重新部署，并重新评估 IQ3_XXS 的调参结果（它们只绑定 v0.1.42）。备份位于 `.tmp/`，删除后就不能用这个命令回退，只能用 [v0.1.41 制品](../../config/artifacts/strata-v0.1.41.json)重新安装。

运行明细只保存在 `.tmp/upgrade-0.1.42/`、`.tmp/iq3-s2/` 和 `.tmp/q2-control/`。完整精度数据见 [upgrade.json](upgrade.json)。
