# rtx3080ti IQ3_XXS 第 5 维：spec（3 / 4 / 5 / 6）

结论：**采用 spec 3**（原默认 4）。按冻结胜者规则，spec 3 批次得分 0.848，次高的 spec 4 为 0.737，差 0.111，超过 0.08，按得分选。Main 与独立复核意见一致，已于 2026-10-11 写入 rtx3080ti 的 `model_overrides.IQ3_XXS`（`"spec": 3`）并部署。

**证据弱，主要是噪声**：
- 其余三个条件的低分都来自一次模型自身的证据格式失误（spec 5 把 `lines` 写成整数；spec 6、spec 4 把区间写成 `[a,b]`），结论分布与其他实例一致。按 ARW 规则这类失误照常计分，按测量规则也不能按得分排除样本；这与第 8 维 0.3 因同类失误出局的处理一致。
- temperature 0 下，spec 机制上不应改变质量，分差主要来自每个条件有没有抽到一次格式失误（本维 12 个实例中 3 个）。同一 spec 4 + `spec-min-p` 0.9 条件，第 8 维批次分 0.837，本维 0.737，相差约 0.1，已超过 0.08 门槛。
- 代价：引擎解码 102.5 对 105.9 tok/s（约 -3%），工作时间持平（14.9 对 14.7 分钟）；每条件 3 次，速度差不显著。

**回退条件**：后续运行中 spec 3 下的格式失误率不低于其他条件，或解码损失持续超过 3% 时，回到 4。

**适用范围**：仅限 rtx3080ti、IQ3_XXS、Strata v0.1.42、Codex high、ARW Commit Audit 单一场景。spec 2 和 spec ≥7 未测，长输出和代码生成也未单独验证。

## 决策记录

- **冻结规则结果**：spec 3。
- **执行 worker 初稿意见**：维持 4。理由是剔除 3 次格式失误后各条件差不超过 0.08，改按速度比较，spec 4 解码最快。
- **独立复核意见**：按规则取 3，不偏离冻结规则。低分实例是模型自身失误，照常计分，不能排除；即使把 slot 4 的整数行号在评分副本中改成数组，spec 4 仍为 0.737；把 `[a,b]` 改读成区间会改变证据本身，不允许。同时指出证据弱。
- **Main**：采纳复核意见，双方一致取 3，写入并部署。
- **部署**：2026-10-11 用 `tools.ops.deploy --host rtx3080ti` 部署，安装目录 `config/deployment.json` 回读为 `"spec": 3`，源文件 SHA 校验通过，前端 lease free、模型未加载。spec 3 的生效已在本维 spec-3 实例中核对（verify window 5）。
