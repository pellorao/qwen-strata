# rtx3080ti IQ3_XXS 第 6 维：CPU 辅助短输入（STRATA_PREFILL_CPU_SHARE 0 / auto）

结论：**auto（当前默认）输入处理更快**，引擎输入 2086 对 1871 token/s（+11.5%，Welch t≈21，三对交错全部同向），引擎输出持平（116.3 对 115.4），两组 9/9 全对。提速集中在短增量：每个小于 1024 token 的分块固定省 0.6–0.7 秒，第 2、3 请求的输入时间约少 1/3；8192 的整块没有变化。按"速度优先"规则保持 auto，默认不变，不部署。Main 与独立复核 agent 意见一致。

适用范围：仅 rtx3080ti、IQ3_XXS、Strata v0.1.42、32K 合成短负载。部署里显式写了 `auto`，与上游默认（不设置）不等价：显式 auto 的分担上限是 3072 token（不设置时 1024），所以 1024–3071 token 的分块也走 CPU 分担（上游在 5070 上测到 2048 token 慢 2%）；本组只覆盖了小于 1024 的分块，而 agent 工具结果常在 1–3K，这一段未验证。显式 auto 时内存不足只警告、不会自动跳过。

## 条件

同[第 1 维](../pcie-frac/summary.md)，加前五维胜者（不传 `--pcie-frac`、all、23 线程、`--ple-io direct`、prefill 8192），只改环境变量。每个实例从唯一的 strata.exe 进程读到的环境变量与条件一致。执行顺序 0-1、auto-1、auto-2、0-2、auto-3、0-3。冻结计划：[rtx3080ti-iq3_xxs-cpu-share-plan.json](../../../../benchmarks/resource-calibration-v1/rtx3080ti-iq3_xxs-cpu-share-plan.json)。

## 结果（每条件 3 次算术平均）

| 条件 | 正确 | 平均工作秒 | 最短 / 最长 | 标准差 | 未缓存输入 | 已缓存输入 | 输出 | 引擎输入 tok/s | 引擎输出 tok/s | 任务输出 tok/s | 最低可用内存 GiB |
|---|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| 0 | 9/9 | 111.7 | 101.8 / 117.4 | 8.6 | 34596 | 65536 | 10742 | 1871.1 | 115.4 | 96.1 | 8.75 |
| auto | 9/9 | 107.5 | 105.2 / 110.0 | 2.4 | 34596 | 65536 | 10563 | 2086.4 | 116.3 | 98.3 | 8.69 |

- 逐请求输入时间：请求 1（33309 token = 4×8192 + 尾块）14836 → 14145 ms（−4.7%）；请求 2（549 token）1789 → 1173 ms（−34.4%）；请求 3（738 token）1865 → 1265 ms（−32.2%）。
- 工作时间差 4.2 秒：输入 1.9 秒（45%），输出少 180 token 约 1.5 秒，解码速率约 0.8 秒；后两项是噪声。
- 日志里没有 CPU 辅助相关行（只有不设置时才打印）；遥测旁证：短输入期间 0 组模型进程 CPU 2–3%，auto 组 52–73%。
- 内存代价约 50 MB（两块锁页缓冲），没有警告。

## 决策记录（自主模式）

- Main：保持 auto。原判断"工作时间差以输出长度为主"不准确，已按复核改为分解口径。
- 独立复核 agent（Opus，max 推理）：条件生效，意见"保持 auto"；指出显式 auto 与不设置的差别，建议在 ARW 或后续对照中覆盖 1–3K 分块，或比较"不设置"。
- 结果：双方一致，默认不变，不部署。1–3K 分块与"不设置"的对照列入待办。
