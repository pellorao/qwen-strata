# Spec Readiness 思考上限诊断（rtx3080ti，IQ3_XXS）

日期 2026-10-12。用户批准（同日改为只跑新设置）：当前默认部署（方案 A：high 思考上限 28672，总输出由 Strata 用满剩余窗口）跑 3 个 Spec Readiness 合并实例，与 F6 的 5 个实例（旧设置：思考 8192、总输出 24576）比较。逐实例数据见 [summary.json](summary.json)，冻结计划见 [plan.json](../../../benchmarks/resource-calibration-v1/iq3_xxs-spec-budget-2026-10-12/plan.json)。

## 结论

- **8192 截断不是 Spec Readiness 低分的主因。** 新设置下思考触顶从每个合并实例约 3.5 次（F6 批 b：2 个实例 7 次，都停在 8192）降到 0.67 次（3 个实例 2 次，停在 28672）。审核变长了（合并实例平均 22.3 分钟、输出 109K，F6 为 16.4 分钟、81K），但 artifact-promotion 仍远低于 v0.1.38 + Q2_0 时期（单段约 47 分钟、输出约 155K）。
- **分数有上升趋势，但样本不足以确认。** artifact-promotion 0.392 对 0.292（差 +0.099，SE 0.084，d/SE 1.18）；融合分（ARW 原版罚分）0.459 对 0.404（+0.056，d/SE 0.84）；扣罚前 0.511 对 0.436（+0.075，d/SE 1.09）。3 对 5 个实例、组内标准差约 0.1，这样的差在噪声范围内，只能说"新设置不比旧设置差，可能略好"。
- **适用范围**：rtx3080ti、IQ3_XXS、Strata v0.1.42、Codex 0.162.0、high。对方案 A 的含义：保留方案 A 没有发现代价；它不能解释 Spec Readiness 与 v0.1.38 时期的差距，剩余原因（版本、量化、启动提示、spec 等同时变化）仍未分离。
