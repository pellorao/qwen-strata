# Code Spec v3 测量报告（IQ3_XXS ×5；rtx3080ti，Strata v0.1.42，Codex 0.162.0）

## 结论

**v3 仍然太容易，需要重新设计。**
- Q3 平均检出 21.8/22 个问题用例：其中 21 个用例 5 次全部检出；用例 6（`room-catalog.mjs:19` 的排序比较器）检出 4 次。
- 计划在看到任何分数之前定好门槛："Q3 原定 5 次平均检出 ≥20/22 → 不跑 Opus，重新设计"。所以本轮没有跑 Opus 参考运行，也没有加测，没有 Q3/Opus 比值。
- 原因：多数缺陷需要比对多个文件，但每个缺陷最终仍落在一行可疑代码上。Q3 逐行对照 spec 读完 10 个模块，5–12 分钟就能全部找到。只把缺陷放到跨文件的位置，并不能让它变难。

**适用范围**：只适用于 rtx3080ti + IQ3_XXS + Strata v0.1.42、high 推理强度。冻结版本为 code-spec-reviewer 修订号 13（c5caef7），变更说明见 `benchmarks/reviewer-suite-v1/code-spec-v3.md`。

## 运行过程

- 批 A 3 个实例，批 B 2 个实例，每批都从头准备、冷启动。开跑前核对 Strata 版本和基础提示 SHA。每个实例都记录了 `strata_release=0.1.42`（3ef7d87 新增）。
- 第一次开跑的批 A 在第 1 个实例运行约 1–2 分钟时被中止，整批作废，不计入样本。中止后租约没有归还，后来由同一个 provider 调用 ARW 自带的 release 归还。之后批 A 从头重跑。
- 路由器重启发生在两批之间，两次租约收尾都正常。
- 会话检查：6 个线程（5 个 reviewer 线程和 1 个 guardian 线程）全部有效。5 个 reviewer 线程的起始上下文相同，没有读取场景根目录之外的文件。被标记的只有两类：工作目录写错、根本没有启动的命令，以及一次写入只读 `/tmp` 的尝试。实例 3 压缩过一次上下文。
- 裁决：1 名全新的 Opus-high 盲裁者，174 个候选中判定 109 个匹配。所有不匹配的候选，都是因为与另一个植入缺陷共用代码行而被关联进来。

1 次 Opus-high 盲裁，174 个判定，约 10.8 万 token。没有 Opus 参考运行，也没有加测。

## 重新设计方向（未执行）

按"难度来自推理深度，而不是更多用例或更多阅读量"的规则：
- 只有把两个模块组合起来才看得出的缺陷：单看每个模块都符合 spec。
- spec 要求某一步、代码却悄悄省略的缺陷，定位锚在本应出现这一步的位置。
- 要动手推算数值才暴露的边界和单位错误。
- 更强的诱饵：看着像错、但按 spec 的某个细节其实正确的代码，用来考查精度。
