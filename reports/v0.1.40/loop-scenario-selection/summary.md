# 防循环对照场景选择

结论：按现存报告中明确的同操作／同错误／无进展证据，选择原版完整Commit Audit场景。它至少有三个独立观测确认工具循环，另有一个独立观测的思考文本循环。98次命令重复只属于其中一个观测，不是选择理由。

| 场景／已记录批次 | 独立观测 | 已确认工具循环观测下限 | 未确定范围 |
|---|---:|---:|---|
| Commit Audit profile及推理批次 | 22 | 至少3 | 另1份思考文本循环；其他观测缺一致循环判定 |
| Spec Readiness上下文合并场景 | 18 | 至少1 | 另3份重复核查／迟写停滞疑似；16份有相同调用额外重复，但16/18不是循环率 |
| Code Standards／Code Spec | 不用于率估计 | 未知 | 无逐实例循环判定，不填0 |

Commit Audit三份为原trained第1（同失败修复98次）、default第2（同失败探针18次并重读不变规则21次）、推理low第5（同错误探针三次原样重试，已有局部诊断核实）；单次思考循环为medium第3。Spec的明确循环为150K补跑；其他三份虽然存在重复核查或未及时写入，现存汇总不足以排除必要检查，因此保守不算确认循环。逐份依据见[JSON](summary.json)、[调用手册的历史异常](../../../docs/installation-directory-readme.md#已观察到的执行异常)及[推理批次诊断](../../v0.1.38/reasoning-effort-comparison/summary.md)。

数值是现存可确认发生实例数的下限，不是完整统一检查后的真实循环率排名。历史版本、强度、窗口和提示条件不同，原日志已删除；不能补做已取消的完整检查、将普通返工算成循环，或认为新版本必然复现。当前选择以可核对的多次发生证据为准，未新增模型运行。

后续三组为无工程追加提示的基础组、仅加现有启动提示全文的提示词组、仅改官方采样的参数组。每组三次、新实例，保留原版完整Commit Audit输入与运行／报告合同，不使用118行合成修复、不复用旧结果或此前六次短兼容性样本。原版任务耗时需要重新估算，不能沿用合成任务25—45分钟或五分钟截断方案。
