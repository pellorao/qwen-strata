# v0.2.12 对 v0.2.11 高压力对比 (2026-11-09, rtx3080ti, `qwen-strata/v0212test`)

只看同配置相对变化，不用绝对速度线。设计经独立审查（opus high，9 条必改项已采纳）；运行计划记在本机的任务记录里（不在本仓库）。

## 结论
- **速度（100K 到 150K 受控批次）：v0.2.12 没有变慢，也检不出变快。** 引擎口径下，冷预填充 +0.3% 到 +1.2%，首请求解码 +0.6% 到 +1.1%，全部请求解码 -3.2% 到 +3.6%（符号随长度变，在噪声内）。此前非受控的 +5% 没有被受控批次证实。
- **智能（Spec Readiness v4.3，每版本 10 个重复，单名 Opus 盲裁）：未检出差异，也未证明等价（open）。** 总分 v0.2.12 0.567（SD 0.051）、v0.2.11 0.557（SD 0.078），d=+0.011，SE=0.029，|d|+2SE=0.069 > 0.05；RM 与 AP 分项同样 open（见下节）。10 对 10 只能检出约 0.08 以上的差异，所以只能说 v0.2.12 没有看到明显变差，不能说两版等价。

## 方法与配置核对
- 版本：A = v0.2.12（Control 与引擎 0.1.58），B = v0.2.11（引擎 0.1.57）。切换用 `upgrade_release --rollback <11-08 升级备份>` 和重新 `upgrade`，各一次成功，P1 到 P3 每阶段断言版本。顺序 P1(A) -> 切 -> P2(B) -> 切 -> P3(A)；速度 A1 B1 B2 A2，SR 块 A1 B1 B2 A2；每个速度段前空闲 300 秒。
- 相同项：24 个速度实例的 `effective-engine-args` 指纹全部相同；4 个 SR 块的引擎启动行指纹相同；主机默认部署（`verify_sources`）一致；内存 5600、GPU 驱动 617.42 三阶段相同；启动提示 SHA `1cae169a…` 与压缩提示按工程基础提示接入；Codex 0.164.0 harness 补丁相同；速度负载和请求选项相同（冻结）。
- 不同项：引擎文件（0.1.58 对 0.1.57，预期）。P1 与 P3 的引擎文件 SHA 相同。
- **未核对**：速度侧 `STRATA_ROUTE_PRIOR=1.5`、`STRATA_ADAPT_LAG=2` 没有在引擎进程里核对（引擎以管理员权限运行，环境读取被拒），按部署的 `model_environment` 假定两版相同。SR 块的 `verify_effect` 通过。
- 偏离：Codex 0.164.0 不换新版（harness 补丁钉在该版，换版牵动补丁）；150K 档保持冻结负载，实际提示约 150,254 token（略超阈值）。

## 速度结果（引擎日志逐段记录，不用 API usage）
每 (版本, 长度) 4 个冷启动实例，共 24 个，全部 closed-valid。每实例 3 个请求：initial-extraction（冷预填充整段上下文），cached-calculation、cached-update（复用前缀）。汇总 = 总 token ÷ 总秒。

| 指标 | 长度 | v0.2.12 | v0.2.11 | 变化 | A2/A1 漂移 |
|---|---|---|---|---|---|
| 冷预填充 tok/s | 100K | 2642.6 | 2612.5 | +1.2% | +2.4% |
| | 125K | 2621.3 | 2589.5 | +1.2% | +1.1% |
| | 150K | 2600.7 | 2593.3 | +0.3% | +0.3% |
| 首请求解码 tok/s | 100K | 173.9 | 172.1 | +1.0% | +2.0% |
| | 125K | 171.3 | 169.6 | +1.1% | +4.2% |
| | 150K | 170.5 | 169.5 | +0.6% | +1.8% |
| 全部请求解码 tok/s | 100K | 154.8 | 153.7 | +0.7% | +7.6% |
| | 125K | 150.4 | 155.4 | -3.2% | -0.4% |
| | 150K | 152.9 | 147.6 | +3.6% | +4.5% |

- 实例间波动（CV）：冷预填充 0.3% 到 2.2%，首请求解码 1.0% 到 3.3%，全部请求解码 1.2% 到 4.4%。同版本 A1 与 A2 的漂移 0.3% 到 7.6%，与版本差在同一量级。
- 按判定线（|r-1| > max(3%, 2 倍漂移)）：冷预填充和首请求解码的版本差都小于 1.3%，低于线，**未检出差异**；全部请求解码 125K 的 -3.2% 和 150K 的 +3.6% 超过 3% 但没有超过 2 倍漂移（漂移 -0.4%/+4.5% 之间互相抵消，符号相反），也不判检出。配对（A1/B1、A2/B2 同遍同长度）12 对的全部请求解码比值中位数 -0.2%，范围 -5.8% 到 +8.1%。
- 全部请求解码里含 cached 请求，其输出量由推理长度决定，变化大，所以放宽；首请求在两版中输出长度相近（3.1K 到 3.9K token），最可比。
- `pass:false` 的请求：A 7/36，B 8/36，比例相同。几乎都是 cached-update，输出触到 8192 token 的预算上限（推理耗尽预算，答案不完整），少数 cached-calculation（B 的 2 个）。这是 reasoning high 下的答案正确率，两版接近，不影响速度结论；速度只用引擎的 token 和时间。
- 逐实例明细：`stress-speed-detail.txt`。

## Spec Readiness 盲裁与得分

**口径（解盲前写定）**：每重复得分取 ARW 的 `scoreBeforePenalty`（总分，RM 与 AP 两个子场景合计）；RM、AP 分项取各自 handoff 的 `score`。每版本 n=10，均值、SD（n-1）、d=v0.2.12 减 v0.2.11、SE=sqrt(s1²/n1+s2²/n2)。判定沿用 `staged_decision`（δ=0.05）：|d| > c·SE 为检出，c 取 n=9 档的 2.5（n=10 不在表内，取偏保守的邻档）；|d|+2·SE < 0.05 才算等价；其余为 open。所有 20 个重复无暂停、无 ARW 截断、格式罚分 f=0，所以扣罚后分与总分相同。

| 分数 | v0.2.12 均值 (SD) | v0.2.11 均值 (SD) | d | SE | \|d\|+2SE | c·SE (c=2.5) | 判定 |
|---|---|---|---|---|---|---|---|
| 总分 | 0.567 (0.051) | 0.557 (0.078) | +0.011 | 0.029 | 0.069 | 0.073 | open |
| RM | 0.854 (0.107) | 0.799 (0.105) | +0.055 | 0.047 | 0.150 | 0.118 | open |
| AP | 0.487 (0.062) | 0.489 (0.092) | -0.002 | 0.035 | 0.072 | 0.087 | open |

- 总分 d/SE=0.36，AP d/SE=-0.05，RM d/SE=1.17，都远低于检出线。RM 点估计 v0.2.12 高 0.055，但 SE 0.047，不能当作改善。
- 点估计下 v0.2.12 总分不低于 v0.2.11；2SE 区间内 v0.2.12 最差比 v0.2.11 低约 0.048（d-2SE）。
- 块间差异：v0.2.11 的 r1/r2 块均值 0.579/0.534，v0.2.12 为 0.581/0.553，块间差与版本差同量级，是 10 对 10 检出力不足的一部分原因。
- 数据：`stress-sr-scores.json`（逐重复 RM、AP、总分，版本与块已解盲）。

**盲裁**：5 个池（150/150/150/150/147 项，每池含 12 个锚点和 9 个合成项），单名 Opus high（`blind Opus high`，brief 为冻结的 Spec Readiness v4.3，sha256 `eaa1df47…`），每池一个 agent，只给池文件、view 和 brief，路径与池内容无版本信息（池文件内容与提示已检查，无版本、主机、运行目录文字）。5 个池锚点一致率都是 1.0、合成项全对，通过门槛，全部写入。复核清单：`supported` 共 19 项（sr-3 3、sr-4 8、sr-5 8），争议 `unsupported` 共 14 项（sr-3 2、sr-4 8、sr-5 4）；这些没有经 Main 复核改判，按盲裁原判计分，未做改判敏感性分析。

**偏离**
- 评分计划的 Codex 绑定：`bench_score --enumerate` 绑定 v1 SR 计划里的 Codex 0.163.0 副本，本机已无。按 Main 决定派生评分用计划副本，只把 `fixed_conditions.codex` 改为 0.164.0、`native_cli_sha256` 改为 `b93f6811…f306`（SR 实际用该版本跑）；`diff` 确认只差这两行。原计划、答案键和评分规则未动，没有重装 0.163.0。
- 20 个实例中 16 个的新鲜准备没有原 prepared.json 或场景副本清单可对照（`preparation_unverified`），答案键契约来自冻结计划；对照另外 4 个通过。
- 盲裁用 Agent 工具的 Opus 子 agent，不是 `claude -p` 无头进程；提示由 `blind_pool prompt` 生成，复制到中性路径供子 agent 读取。

**不能说的**：不证明两版等价；10 对 10 的 SE 约 0.03 到 0.05，检出下限约 0.08；一个 Opus 盲裁者的主观口径对两版相同，但每个池里两版实例随机混合，所以不引入版本偏差。
