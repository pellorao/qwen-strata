# adaptfetch：`STRATA_ADAPT_FETCH` 关 / 1 / 2（rtx3080ti，IQ3_XXS，Strata v0.2.12，2026-11-08）

只测量，生产未改。来源：v0.2.12 新开关，上游唯一数据是 IQ3_S、RTX PRO 5000、缓存仅 16% 专家、`--pcie-frac 0.25` 下解码 `=2` +10.2%、`=1` +5.0%（命中率 54-61% 升到 71-78%）。

## 结论
本机生产配置下，三组**没有可检出的差别**：所有项目都在噪声内（|z| <= 2.1，且 2.1 那一项在 12 个比较里属于预期的偶然）。建议不改生产，`STRATA_ADAPT_FETCH` 保持未设置。

## 设计
- 临时 native 服务，127.0.0.1:8199，经前端领租约停模型后运行（租约全程持有，结束归还）。已装配置原样（含 `STRATA_ROUTE_PRIOR=1.5`、`ADAPT_LAG=2`、MTP `--spec 4`、没有显式 `--pcie-frac`，PCIe 份额由引擎自动取 0.15），只加 `STRATA_ADAPT_FETCH`（关 = 不设）。三组引擎启动日志：1、2 有 `STRATA_ADAPT_FETCH=n: the PCIe share takes ...` 行，关没有，即开关在本机配置下确实生效。
- 9 次冷加载，按块交替：关 f1 f2 | f2 f1 关 | 关 f1 f2（每组 3 次加载）。每次加载后：1 次 warm，4 个短提示（700 token 上限，关思考）、M（约 2.9 万 token 提示）、L（约 11.9 万）x3 的解码与读入，再 2 个长生成任务（pure-1、pure-2，开思考 high/8192，上限 24576）。提示与 memspeed2 驱动一致（`driver4.py` 派生自 `driver3.py`）。
- 速度取引擎日志的 `tok/s`（v0.2.12 口径，三组同一口径）；长生成为逐段生成数 / 生成用时。主机无其他重负载（未使用 resmon 逐次核对，三组 SD 与 memspeed2 同量级）。
- 写盘：约 2.2 MB。

## 解释
- 噪声：同组跨加载 SD 为均值的 1-5%（M、L 的关组 SD 更大，7-13%），12 个比较里只有 f2 短故事2 的 z 达 2.1，其余 |z| < 1.1；最大均值差 +3.8%（M，SD 19.5，n=3）。3 次加载的精度只能排除约 5% 以上的变化，不能证明 0%。
- 为什么没有上游那样的收益：上游场景的专家缓存命中率只有 54-61%，开关把它拉到 71-78%。本机 IQ3_XXS 的解码命中率在关组已是 97.5%（引擎日志，f2 为 97.8%），可提升的空间极小，所以增益不显著。
- 输出质量：开关只改放置（哪些专家常驻），上游 token 强制测试判不影响输出（不匹配率差 +0.19 pt，PASS）；本次未测质量，也没有理由测，因为速度无收益。

## 偏离与遗留
- 样本为 3 次加载 / 组，没有加测；差异若小于约 5%，本测量判不出。未做加测的理由：点估计在零附近且方向不一致，命中率机理也解释了为什么没有收益。
- 临时服务 14 个 STRATA 环境变量 / 子进程环境已核对（`child-env.json` 在 `.tmp`），ROUTE_PRIOR=1.5 在所有组中。
- 操作教训：`schtasks /end QwenStrataFrontend` 只结束前端，常驻的模型进程（`strata.exe`，约 45 GB）要再过约 6 分钟才自行退出；更好的办法是不 end 前端，直接用 `Controller` 领租约（`with` 块会停模型并冷启动），本次中途改用了后者。
- 原始明细在 `.tmp/adaptfetch/`（驱动 `driver4.py`、`hold.py`、`an.py`）和 Windows 临时目录 `Temp\adaptfetch\both\`，不入库；数字输出见 `an-output.txt`。
