# 动态防重复调用三次本机对照

结论：动态保护能够通过原版 ARW 把提醒送入 Codex，但这三次诊断没有证明它能稳定减少循环，不能据此替代当前防循环提示。唯一一次实际提醒后，模型仍提交了两次改过文字但保持同一缺括号错误的脚本。日常默认不变，接着执行已批准的 IQ3 单独对照。

仅候选启用原版 ARW 动态命令保护；两组都排除静态防循环段，保留其余完整启动与压缩提示。Strata 0.1.40.1、Codex 0.160.1。

| 原基线 | 0 / 3 / 2 | 0 / 393 / 17 | 136.7 | 17 | 2/3 |
| 动态保护 | 3 / 5 / 3 | 14 / 29 / 26 | 23.0 | 26 | 3/3 |

次数均值下降83.2%，但原基线第二次包含连续379次字面重复，主导了均值。候选中位数反而从17增至26，三次都出现循环，不能把均值下降当成可靠疗效。循环次数包括每组初始重复行为，汇总所有组；额外重复次数等于总次数减组数。普通逐要求映射、真实证据核查、工具镜像和有效修复不计循环。

四项速度各按逐次算术平均：引擎输入2942.706、引擎输出125.080、任务输入≈1768.320–1921.264、任务输出≈39.019–42.524 token/s。第三次后段引擎变慢的原因尚未验证。

所有三次均已逐条核查完整原生会话、118项判断和各自finding。三次都主动查询环境运行身份、普通单文件沙箱失败并未及时写finding，正式验收失败；第三次最终通知使用错误运行ID，且最终状态带代码围栏。原报告完整，Main原版生成成功，只保留诊断得分，不因失败重跑。当前评分对“临时字节确定泄漏”的无依据断言拒绝关联，旧基线对此类不透明Adapter合同的历史裁决可能不同；不追改旧分数，不以本组分数差推断质量因果。

保护只识别连续三次命令、目录、退出码及可用输出摘要都相同的情况。第三次第三个相同结果后发送提示，模型到第四个相同探测结束才实际收到；收到后两次更改探测仍保留缺右括号错误，随后压缩并结束。推理内循环及改过命令的语义循环超出该检测规则。
