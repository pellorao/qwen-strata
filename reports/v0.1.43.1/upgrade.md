# v0.1.43.1 升级（本机）

2026-10-13，用户决定在 Code Standards 之前升级 Strata 并完成升级后的例行工作；从 v0.1.42 直接升级到 v0.1.43.1（跳过 v0.1.43）。

## 结论

- 本机已升级到 Strata v0.1.43.1，**通过短检查**（IQ3_XXS，一个实例，每项一次）。检查经由实际使用的 `bin/qwen-agent` 入口，覆盖 Claude Code 和 Codex。
- 本次只是短检查，不代表完整验收，也不继承 v0.1.42 的结论。上游称 Windows NVIDIA 默认配置下回答与 0.1.42 逐字相同（只有用户文本引用 `</tool_call>` 时不同），本次没有验证逐字一致。
- 参数沿用 v0.1.42 上的 IQ3_XXS 调参结果，没有改任何默认值；调参结论绑定 v0.1.42，在本版上未重新测量。
- 计量工具已适配新日志：v0.1.43.1 新增一种分块诊断行（#2090），`tools/metrics/strata_tokens.py` 原先会把它误判为不完整的 token 记录而报错，已修正并加测试。短检查 13 个请求全部解析成功。
- 新出现的提示：13 个请求中有 2 个开始时显存只剩 128–276 MiB，引擎按 #2065 新增的检查发出警告，建议 `--vram-reserve-mib 1280`。本次速度正常，没有改；见下文"待观察"。

## 短检查（IQ3_XXS）

只有一个实例，每项跑一次，不取均值，也不算正式评分。每个阶段是一次独立的 `qwen-agent` 运行。C1 冷加载模型，之后的阶段复用已加载的模型。工作目录放在工程目录之外，避免带入工程上下文。

主机条件：BIOS 1.C0（微码 0x137），CPU 功耗档 Intel Default Settings（PL1 65 W），内存 XMP 6600；22:12 正常重启后的第一次加载。

## 待观察

- **显存告警（#2065 新增的检查）**：C1 的 13 个请求中有 2 个开始时剩余显存为 128–276 MiB（低于 1024 MiB 的告警线），引擎建议 `--vram-reserve-mib 1280`。上游说明这时驱动可能把显存换页到内存、解码掉到几 tok/s。本次没有出现降速。显存预留 512 是 v0.1.42 调参按"用满"偏好选的（768 与 512 速度打平，均快于 1024，见[调参手册](../../docs/calibration.md#iq3_xxs)）。是否调整需要在长任务中观察告警频率和是否伴随降速，再决定是否测量；本次不改默认值。
- 上游 #1622 仍未关闭。
