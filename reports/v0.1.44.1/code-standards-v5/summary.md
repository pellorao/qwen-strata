- 场景：Code Standards v5.1（修订 25，答案键 `3950875c`，两类计分 A 类 10:10）。主机 rtx3080ti，IQ3_XXS，Strata v0.1.44.1，推理强度 high。

## 版本

- v5（修订 24，冻结 b00c05a）上测完 Q3 ×10 和 Opus 前 2 次后，发现重复类题（S17–S25）要求发现同时写出被重复一端的具体行号才能关联。Q3 和 Opus 常只写对端文件名或符号，正确的发现因此记为漏报，又让 noOther 失败。独立裁决 agent 认定这是答案键缺陷。
- v5.1（修订 25）：重复类题的关联证据只保留变更端的行，对端是否写对由盲裁判定；对端行号仍计入证据定位分 F2。另外修掉 clean #21/#28 中会被拆词误撞的多词 term。只改答案键，代码与题目不变。
- 冻结产物：`benchmarks/reviewer-suite-v1/arw-patches/code-standards-v5.1.patch`（`09f02f20`）、`source-snapshots/current/manifest-code-standards-v5.1.json`、计划目录 `code-standards-v5.1-iq3_xxs-2026-10-15/`。检查：conformance 70/70，54 个变体 verify/lint/餐饮测试全过。
- Q3 ×10 与 Opus 前 2 次的回答在 v5.1 键上重算，不重跑模型；Opus 第 3 次直接在 v5.1 计划上运行。

## 偏离

1. v5 期间曾用加了强制开关的计分模块副本补关联（裁决接口不支持补关联和 clean 改判）；v5.1 重算全部走正常入口，分数与当时一致，强制口径作废。
2. v5.1 重算没有重跑 prepare，而是在每个运行副本中换入 r25 答案键与修订号；重复题已裁候选沿用原裁决，只把新候选送去盲裁（规则要求受影响用例的候选全部重裁；期望句未变）。
3. 生成 r25 补丁时额度脚本已返回 exit 1，命令未拦住；该步只在本地运行，不调用模型。
