# 内存 DDR5 6600 → 5600 后的 Strata 速度（rtx3080ti / IQ3_XXS，Strata 0.2.11，2026-11-08）

只测量，生产未改。结论：内存降到 5600 后 decode 速度低约 5-10%（长提示约 5%，噪声内；短提示约 10%，部分提示超出噪声），读入速度低约 3-4%；草稿接受率没有变化。

## 基线与条件
- 基线：routeprior2（2026-11-07，内存 6600）速度测量的对照臂 C（不加 `STRATA_ROUTE_PRIOR`，即生产配置），数据 `reports/routeprior2/speed.txt`。
- 本次：同一驱动 `routeprior2/driver2.py` 的 speed 模式（输出目录名与调度改为 C×3），同样的提示（4 个短提示、M 2.89 万 token、L 11.9 万 token ×3）、关思考、温度 0、各 700 token、每次冷加载后先预热。
- 一致：代码与配置（`git log -- src config` 最近改动 2026-11-04，早于基线）、模型、量化、同一临时进程方式（127.0.0.1:8199，停前端）、提示文本、重复次数（C 臂 3 次冷加载）。
- 差异：内存 6600 → 5600（ConfiguredClockSpeed 已确认 5600）；基线的 C 臂是 6 次加载中的第 1、4、5 次，本次是连续 3 次；基线当天主机状态不可复现。基线只留下汇总，没有逐次读入速度（speed.txt 的 read 列为 None），读入对比只能用报告里写的 L 约 2640 tok/s。
- 主机无重启，无降速 <60 tok/s，无实例超时，3 次加载 14.2/16.2/16.2 秒，显存峰值 11425-11593 MiB，内存占用峰值 91.7-93.5%。

## prefill（读入）tok/s

|---|---|---|---|
| L 11.9 万 | 约 2640（基线报告） | 2547（SD 20，n=9） | 约 -3.5% |
| M 2.89 万 | 无记录 | 2403 | 无法比较 |

L 的 5600 读入速度三次加载内很稳（SD 20），低于基线约 3.5%；基线没有 SD，不能判定是否超出噪声，但与前一份 routeprior3 里 "prefill 低约 5%" 的结论方向一致。

## 结论与意义
- 内存降频使 decode 平均慢 5-10%，prefill 慢约 3-5%；草稿接受率逐提示相同（0.83-0.95），所以不是投机行为变化，而是带宽带来的单步耗时。
- 短提示受影响更明显（-10%），长上下文 decode 在噪声内（-5%，中位数持平）。
- 对 agent 工作负载：此前 routeprior3 里同一工作负载每实例用时无明显差别（500 对 532 秒，SD 约 100 秒）；本次标准速度测量说明代价约在 5-10%，折算到以 decode 为主的 agent 回合是个位数百分比，远小于实例间波动。5600 是为查断电重启而降的，只要主机因此稳定，这个速度代价小于一次重启的损失。
- 局限：基线为单日一组（3 次冷加载），逐次原始数据已不在，无法做配对检验；短提示 n=3，SD 估计粗。主机在 5600 下整个测量期间无重启，可作 5600 稳定性的一点证据（约 20 分钟）。
