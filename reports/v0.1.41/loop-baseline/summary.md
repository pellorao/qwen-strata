# 无防循环提示、无提醒的基线（3 次）

2026-10-11。条件与[提醒组](../loop-reminder-trial/summary.md)完全相同（rtx3080ti、Strata v0.1.41、Q2_0 / high、Codex 0.162.0、冻结 ARW 760007c 加 Codex 0.162 兼容补丁、完整 Commit Audit），只改两处：

- **去掉防循环提示**：启动提示只去掉 "Progress and loop prevention" 一节，其余部分和压缩提示照常接入。实际加载的启动提示 SHA 为 `1cae169a…`，源文件 SHA 为 `5f9efc02…`，驱动核对一致。
- **关闭服务端提醒**：Codex 的每个请求都带 `X-Loop-Reminder: off`。事先用本地假服务器确认 Codex 0.162 会发出这个请求头；运行期间前端日志没有任何提醒记录。

完整数据见 [summary.json](summary.json)。

## 结论

- **这个场景里，不加提示、不加提醒，模型也很少循环**：3 次运行没有确认的跨步循环，也没有步内退化循环。只有 1 处边界情况：实例 2 第 10 步按需求逐条重走了一遍，但第 7 步的审计被推理预算截断、并未走完，第 8、9 步又用 node 拿到了新证据，所以不算确认循环。
- **两组对比看不出防护的作用**：提醒组（防循环提示 + 提醒）有 1 处步内退化循环（漏报）；基线组没有循环，只有 1 处边界。得分 0.699 对 0.656，各次得分的范围相互重叠（0.586–0.798 对 0.550–0.718），以 3 对 3 的样本，差异不能与运行间的波动区分开。
- **基线平均更慢，原因与循环无关**：基线实例 3 用了 13.5 分钟，原因有两个：它用 `nl` 取行号，而 `nl` 会跳过空行，全部证据行号返工；中途又触发了一次上下文压缩。另外两次分别是 6.9 和 7.2 分钟，与提醒组相当。
- **推理被预算截断的步骤更多**：基线 7 次，提醒组 4 次。截断都发生在整段审计或长时间斟酌的步骤上，截断后模型都继续正常推进。这个差异是否与去掉防循环提示有关，样本太少，无法判断。
- **如果基线开着提醒**，检测器会报 12 次（2 / 3 / 7）。这批没有确认的循环，所以这 12 次基本都是误报，也说明当前规则在长审计任务上的误报偏多。

## 会话检查

3 个原生会话的全部工具调用都在各自的场景根目录内。三次都读取了场景根目录的 `.prepared`，内容只有一行准备标记 `commit-audit-reviewer:19:default`，不含期望或答案。实例 3 在推理中注意到 capability 目录里的 `input.json`，按指令决定不读，也确实没有读。会话中出现的 `expected` 都是模型自己核对需求覆盖时用的变量名。实例 3 发生 1 次上下文压缩，压缩后重读 request 和源码属于正常恢复。

## 不能推广的部分

- 只有 1 个场景、1 台主机、1 个量化和强度，每组 3 次。
- 推理预算（8192 token）在两组都保留着，它本身会截断推理内的退化循环，所以基线并不是"没有任何防护"。
- 结论只说明这个场景里循环少见、防护的作用测不出来，不说明防护在其他场景无效。
