# 资源校准短工作负载

本材料用于CPU／RAM／VRAM资源参数的逐维吞吐比较，不是正式Reviewer能力测量，不替代冻结ARW的业务输入、评分或会话检查。生成源为[workload.py](workload.py)：固定合成物流记录，三个请求依次执行字段提取、余量计算和更新后重算；每项核对完整JSON与全部28条结果。期望结果只由Main校验，不加入模型请求，也不进行profile训练。

准备时用固定Q2_0 tokenizer离线选择使共同用户输入接近32K token的记录数，冻结记录数、输入／问题／期望SHA、tokenizer版本与SHA。32K是用户材料的近似长度；真实服务包装、基础提示、thinking收尾及缓存命中以内部原始计量为准。后三个问题保留相同来源前缀，分别记录首次读取及复用表现，不把缓存输入算成未缓存处理速度。每个独立实例重新启动模型、使用相同default/no-save；OS文件缓存不强制清空，按交错顺序平衡，并记录启动／缓存条件。

每项工作首次开跑前固定候选、有效实例和请求范围，给出预算并取得用户同意。保持Q2_0/high、8192思考／24576总输出、temperature0/top_p1/top_k20、100K阈值／156584容量、其他引擎选项和全量工程基础提示；预期不触发压缩，但仍保存工程压缩与版本补充的组合和来源绑定。领取独占key；模型启动、状态、请求、停止与归还均使用控制器。实验只改进程选项，尚未选择前不改部署默认。

每条件三个独立实例，每实例依次执行三个请求；同一条件各次编号独立。CPU亲和性首轮仅改变pool-affinity，worker数23固定，候选auto与all；本机六实例、18项逻辑请求，交错顺序auto1、all1、all2、auto2、auto3、all3。之后的worker数量、RAM和VRAM维度分别冻结／授权，不能将本轮授权扩展为全参数矩阵。

每项逻辑请求累计工作上限150秒，正常已完成的JSON直接检查；正常早停而任务未完成时保持相同来源与参数，用已有回答接续，不重置预算。正常接续不是新有效样本，真实请求数和额外消耗另计。协议／连接故障按现有影响评估恢复，保留原失败；未知执行不自动重复。超时或语义错误不能为提高表现筛选重跑。模型实际启动及卸载、等待下一项和Main介入休眠单列；请求内推理、等待、必要恢复及结果核查计入任务工作。

逐实例统计三类内部token、输入处理／解码秒数、四项速度、工作总秒数、每项正确／完成状态和启动／停止结果；配置逐次取算术平均、最短／最长及总体标准差，未知不填零。由内部日志逐执行段计量，包含真实续生成与收尾，不以API usage取代。确认停止后才读取最终日志，跨阶段避免重复。若增加采样遥测，冻结采样频率并保持各条件一致，不把短暂峰值或占用率当成吞吐改善。

选择以正确、完整且实际工作更快为前提；小于噪声或重复间差异大的效果保留不确定，不仅凭单次最快或资源占满采用。短工作负载收益不能推广成完整Commit Audit／长上下文可靠性收益。运行明细放临时目录；闭合后长期摘要与完整精度统计才进入reports，不发布进行中的模型结果。
