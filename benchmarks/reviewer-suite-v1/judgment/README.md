# k 标记（k 分档计分）

k 分档计分（评分 r8，用户 2026-10-15/16，规则见 `.claude/rules/reviewer-suite.md`「评分」）给每个用例一个档位 k：默认 0.25，难以核实的用例按影响定为 1 或 4。本目录存放冻结场景的 k 标记，不改冻结件。r8 之前的两类计分把用例分成 A、B 两类；迁移时 A 类按 k = 1、B 类按默认档读取，下文"A 类""B 类"的历史判定按此理解。

## 文件

- `registry.json`：登记表。把每个已知答案键（reviewerId 和 `expected.json` 的 sha256）对应到一个覆盖文件，或写明 `in-key`（k 标记直接写在答案键用例的 `k` 字段；两类计分的 `judgment: true` 按 k = 1 读取）或 `all-B`（全部按默认档 0.25）。
- `<场景>.json`：覆盖文件。字段有：
  - `reviewerId`、`expectedSha256`：所标记的答案键。
  - `counts`：标记的正例数和反例数。
  - `cases`：每个标记用例的 `scope`、`kind`（`problem` 或 `clean`）、`index`（0 起）、`expectation` 原文、标定理由 `reason`，以及档位 `k`（1 或 4，不写时为 1）。

- `repeats.json`：重复出题的豁免表（用户 2026-10-16/17：同一道题只出一次，两个子场景之间、同一答案键内部都不得重复）。计分入口对每个答案键检查：noOther 之外的用例期望句相同，或证据相同（clean 的 `evidence` 或某个 `evidenceAlternatives`、问题用例某个 placement 的 `evidence`），就报错。两种例外：`legacy: true` 的旧版本答案键（已被新版本取代或改题前的原版，只用于复评旧回答）；`sharedEvidence` 逐组列出的、经审查确认是不同问题的共用证据用例（`scope/kind/index`，0 起，附理由）。期望句相同在非 legacy 答案键里一律报错。此文件不复制进 ARW。

计分入口（`tools.reviewer.freeze_arw_source.upgrade_scoring`）会检查副本里的每个答案键。答案键没有登记就报错。覆盖文件与答案键对不上、`counts` 不符，或某个标记档的正例数不等于 k 乘反例数，也报错。登记为 `in-key` 的答案键必须带有标记且每档平衡；没登记为 `in-key` 的答案键带有标记，说明登记与实际不符，同样报错。检查通过后，把登记表和所用覆盖文件复制到 `<arw>/reviewer-judgment/`。ARW 加载答案键时再核对一次，并在计分结果的 `judgmentBinding` 里写明所用覆盖文件的名字和 sha256，标记在答案键里时写 `in-key` 和答案键 sha256，全按默认档时写 `all-B`。

新的场景版本（包括草稿）都要先登记才能计分；还没有标定的版本登记为 `all-B`。

k = 4 暂不可用：它的误报须双裁，双裁流程实现之前，答案键或覆盖文件里出现 k = 4，计分入口和 ARW 都报错。

两点限制：
- r7 下准备的实例，准备状态里只有 `judgment`/`judgmentShare`，按 k = 1 读取，表达不了 k = 4。答案键改成含 k = 4 的覆盖文件后，这类实例要重新准备（或重新绑定）再计分。计分读的是准备状态，不会重新加载答案键。
- 冻结检查按覆盖文件或答案键里的用例数核对每档平衡，计分时按实际拆出的子场景核对。Spec Readiness 某个 k ≥ 1 正例若被全量审查的选定范围过滤、又不在需求范围里，它不属于任何子场景，冻结检查能通过，计分时才报不平衡（报错，不出错分）。新标定的场景要按拆分结果再核对一次。

## 分界标准

按两点定档：结论能否简单核实（对照选定 Input 的原文就能核实，不需要多步推理），以及判错与漏判哪个影响大。

- k = 0.25（默认）：可简单核实的用例，例如违反规格、缺陷、漏洞，以及与它们对应的合规写法。误报可以用具体输入、复现、测试或对照规格核实，main agent 能排除；漏报的代价是误报的 4 倍。难以核实但判错影响比漏判小的用例也在这一档。
- k = 1：难以核实，判错与漏判影响相当。例如该不该合并：不该合并的被合并了，可能引入严重 bug，main agent 也未必拦得住。
- k = 4：难以核实，判错比漏判影响大。

每个用例独立判断，不配对；同一题型的正例和反例同档。每个计分单位中，每个 k ≥ 1 档的正例数要等于 k 乘反例数，这样"一律报"和"一律不报"在该档都得 0。Spec Readiness 的计分单位是一次重复（RM 与 AP 合并）；两个子场景不出同一道题（v4.3 起，见[测量规则](../../../.claude/rules/reviewer-suite.md)），没有份额规则。标定只看场景、答案键和设计说明，不看模型结果；生效前要经独立审查。
