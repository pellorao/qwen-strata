# 无关键词的动态文本检测规划

用户要求机械规则不以关键词判断重复。全部／大部分文本可比较，但比较内容必须来自当前任务运行中实际收到的消息，不能预置测试片段或固定回答。旧第一批仅收窄`reasoning-return`历史的方案已撤回：其关键词线索、停用词与词根集合仍参与判断，不符合新约束。旧代码及首轮结果仅保留为历史开发证据，不能继续作为新批次候选或推广到harness。

机械方案拟比较同任务已可观察的完整响应、完整段落／自包含结构块，以及实际工具输入／结果。参照文本由实时采集取得，绑定线程、回合、工具身份及来源SHA；测试真值和未来记录不进入检测器。不按某个词筛选段落，不把长消息任意切成极短片段后用共享词冒充大部分匹配。归一化先只处理排版空白，保留标识符、数字、实际输入和结果的变化；比较算法／长度或比例阈值须在实施前提交具体批次审核。

全文完全相同的对照可直接采用动态内容SHA／逐字核对；近似匹配则须证明两个比较单位各自的大部分文本一致，并提供实际非重叠见证。不能只比较关键词集合。结构解析可识别实际收到的完整JSON或工具结果，但不预置字段值或案例内容；错误类型的解析也不能单独证明循环，仍须比较实际失败上下文。继续指令不豁免相同结果；具体新任务输入或真实进展按来源记录判断，不用某个提示词自动重置。

只读可行性核查比较17个Main边界明确组的实际完整见证片段，不运行新检测规则。仅压缩空白后，14个语义思考组没有逐字相同的见证对；其中13组的最高完整片段字符相似度为0.2701363073110285—0.4585987261146497，另1组0.7131147540983607。3个相同结果JSON组的完整见证均逐字相同。方法、各组完整精度及SHA见[可行性数据](dynamic-text-feasibility.json)。这是选定见证的字符对照，不是156组全集召回率、F1或所有可能算法的不可行证明；局部更短公共片段也不能自动作为“大部分文本相同”的依据。

结论：动态文本比较可以实现直接／大段重复检测，但现有证据不足以承诺覆盖大幅语义改写。全集156组真值、正常记录及联合F1＝1门槛不变，语义重复不得从分母移除。若用户选择先做机械方案，先规范化因果评分输入并提交具体比较单位／阈值／重置／优先级批次，获批后自动实现、评分、Main复核和同代码标签更正重测；未达门槛不申请模型试跑。

用户已明确允许代码调用本地分词／token工具，并进一步允许低资源的快速本地小模型。工具及权重可在准备阶段联网下载；运行阶段全部本地、离线，不依赖agent或远端服务。不得要求独立GPU，ARW机器可能没有独显。Main离线误报复核保留；运行时不通过agent裁决。

已实现[本地文本特征计算](../../tools/loop/local_text_similarity.py)，对完整输入的全部Unicode切分单元及字符三元组形成向量，不用关键词、停用词或预置案例，4项边界回归通过。这些切分单元不是Strata消费token。只读对照17个边界明确正组与89条Main已核查正常候选，三单位最小余弦的最佳组合仍存在显著重叠：正组token余弦0.42135048580019224—1.0，正常候选0.10266546979569642—0.876577924720926；字符三元组正组0.25943947827229996—1.0，正常候选0—0.6560181070550919。完整精度见特征数据（`local-feature-feasibility.json`，已移除）。这是选定单位的表征对照，不是完整因果F1或固定阈值验收；词序／否定变化可出现高相似度，不能据此直接判循环。

本地语义候选选用多语言MiniLM量化ONNX；原模型[官方说明](https://huggingface.co/sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2)给出384维、128-token序列与mean pooling，支持50种语言；[ONNX制品](https://huggingface.co/Xenova/paraphrase-multilingual-MiniLM-L12-v2/tree/main/onnx)的量化文件约118MB。每个下载文件仍按工程200MB限额及完整SHA规则核对。当前准备CPU版ONNX Runtime、NumPy及本地tokenizer；不安装CUDA运行依赖。

CPU编码入口（`local_semantic_encoder.py`，已移除）只加载本地校验文件，明确选择`CPUExecutionProvider`、1—2个计算线程、关闭线程空闲忙等及遥测；缺文件直接报错，不联网取源。长文本按实际完整token序列分块覆盖全部内容，不使用默认截断；分块平均是近似表征，需检验其信息损失。3项不加载模型的准备回归已通过，CPU库导入验证不等于模型推理或资源验收。

已按用户本地小模型授权完成一次固定[CPU资源／表征评估](../../reports/v0.1.40.2/local-semantic-encoder/summary.md)：17个重复组、89条正常候选，283份去重完整文本、84463内容token、821次短编码，初始化及编码worker12.826895882986719秒，RSS采样峰489.8MiB，实际provider仅CPU。两逻辑CPU／1GiB采样停止／600秒时限未触发；全部token覆盖，没有Strata请求、agent或新循环判断。资源条件满足，但语义余弦正例0.4258514700969322—0.999999979340847与正常候选0.10542547676068986—0.8219784382835817重叠，不支持直接用单阈值触发提醒。

下一步结合动态全文／结构与实际任务进展提出第一批机械判断，先规范化因果评分输入；语义向量只作可评估特征。保持156组真值及F1＝1，实施前审核具体单位、阈值／重置／优先级；本轮CPU可行性不表示默认启用、部署或ARW跨平台验收。新的模型／独立评估组仍先交付范围和预算，不能自动追加。样本可通过长期入口（`prepare_semantic_feature_pilot.py`，已移除）从永久引用重建，无需保留完整临时向量。

用户进一步提出由小模型直接看两段文本，联合评分评估现已[闭合](../../reports/v0.1.40.2/local-pair-similarity/summary.md)：2651次CPU联合前向、worker48.3秒、RSS采样峰211.3MiB。两类特征分数仍重叠，7条代理误报Main核查后全部保留正常，不采用单阈值或改真值。通用STS相似度与“同一步骤且没有进展”目标不同；用户允许少量案例快速验证，并已确认[目标定义](work-step-definition.md)。8种行为复用现有评分核查，额外推理0。用户新增优先中型低bit模型，现已准备4B量化指令模型8例任务分类方案（`work-step-model-selection.md`，已移除），制品／预算／方法待审核，尚未实施检测合同或执行新推理。之后按具体组推进，不自动追加全量评估、另一候选或Strata试跑。
