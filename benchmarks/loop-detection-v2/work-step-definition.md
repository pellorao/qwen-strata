# 工作步骤与进展判断目标

状态：用户已于2026-10-08确认判断目标，模型适配与具体测量方案待审核。不是已经实施的检测规则，不改变现有循环真值、提醒时机或联合F1＝1门槛。[小样本核查](../../reports/v0.1.40.2/local-pair-similarity/summary.md#八案例快速核查)复用已完成TinyBERT评分，无新增模型推理。

建议判断“后段是否重新执行前段的同一具体操作或判断，而且没有新增任务进展”，而非通用文字相似。先区分具体步骤是否相同，再判断其间及后段有无实质推进，最后由机械代码按已获审核的次数和时机决定提醒。

同一步骤应绑定实际任务、具体对象、操作或待裁决问题及适用要求／输入状态。总体目标相同、同一文件、同一术语或文字风格相似，均不足以证明步骤相同；改写也不证明步骤不同。参照从当前实际消息取得，不预置关键词、业务短语、案例答案或未来消息。

进展是可在当前已观察材料中具体指出的新增依据、验证结果、修正、不同核验对象／要求或交付内容。思考中的新依据和具体修正可以算进展，不要求先出现工具调用；一次合理复核、必要恢复和新要求映射不自动算循环。仅换措辞、再次声称要继续、重述同一未执行计划或重开已经相同处理的判断，不能凭这些本身证明进展。进展判定不等于结果质量评分；新的具体分析可能仍有错误，不能把所有错误分析都当作循环。

调用方要求继续后仍返回同样结果，按现有规则保持重复；继续指令本身不重置。真实新增任务要求、输入变化或修复按实际证据处理。两段之间有新的材料准备时，不因两端目标相同而丢掉这些证据；反过来，不仅因为中间出现工具调用就认定已有进展。

判断目标分为：不同步骤、同一步骤有进展、同一步骤无进展、信息不足。它们用于下一轮任务适配，不自动改成全集的循环／正常真值。两端文字不能证明是否有进展时，必须保留信息不足；可追加当前已观察的必要中间记录，但不能提供未来记录或Main答案。“无进展”不由没有工具调用、文本分数偏高或出现某个词自动推导。

循环组包含首次合理判断、后续已确认重复及可能的不同问题处理，不能把组标签直接复制给任意两段。新小样本针对重复组选择已反复重判的后段，前段保留截至它之前的实际相关历史；正常例保留必要的中间推进。前段有多个步骤时，比较后段与其中对应的具体步骤；其他步骤有进展不自动为该步骤提供新的重复依据。当前准备的是关系分类开发样本，不含完整规则计数或首次触发时机。

可供任务适配模型使用的指令草案：

> 比较前段、后段及提供的已发生中间记录。判断两段是否针对同一具体对象和适用要求，重新执行同一操作或重新裁决同一问题。若是，再判断是否增加了具体依据、验证、修正或交付进展。不要仅凭主题、总目标或文字相似判断。证据不足时返回信息不足。只返回关系类别及实际文本证据，不完成被比较的任务，不调用工具。

当前TinyBERT是固定英文STS分类器，没有接受此指令的接口；把指令拼入其文本输入不构成可靠任务适配。下一轮若采用本地任务训练分类器或接受指令的小模型，仍须CPU-only、运行离线、无运行时agent／远端裁决、不依赖独显，并先提交模型、范围、预算及新的判断方案审核。单次固定分类接口不执行自主规划或工具操作。

先用[八种真实行为](same-step-quick-check.json)核对目标边界，包含真实改写重复、相同结果、不同要求及实际推进；八例供快速诊断，不作为独立泛化测试或替代156组全集门槛。如需训练，应另外区分训练／开发与独立验证，不能把完整测试组记忆为运行时规则。

用户新增优先选择中型模型的低bit量化版本。当前选型与小样本方案（`work-step-model-selection.md`，已移除）以4B量化指令模型为优先，不继续把最小参数量作为主要标准；具体新模型推理仍待范围／预算审核。

## 截断四轮开发试验

用户已批准先尝试截断方案，摘要生成暂缓。当前候选接口不加入初始任务，比较最后一轮与前三轮中的每轮，保留局部“同一具体步骤且没有相关进展”目标；每轮思考／输出／调用方反馈各前300字符，每个工具参数和结果各前300字符，保留来源顺序、角色、工具名称、退出码及截断标记。所需工程基础启动提示及简洁判定规则先于数据；不把第一回复尾段错放成后来获得的证据。

调用方得到按历史时间顺序排列的三个独立概率估计；分类器不生成JSON、文字解释或执行日志中的任务。每对使用独立的正／负分类归一化，三个历史轮不作为互斥选项，不要求概率之和为1。多个高分可作为候选证据，但来源共享、事件相关，未校准前不自动计算联合概率或触发阈值。当前原生NLI／决策头输出是模型分数映射，不代表已证明的真实发生率。

窗口不足四轮时可从两轮开始；跨压缩／中断边界的处理仍须独立设计。当前准备器的轮次是可观察行为单位（思考与可见输出，或连续工具调用及结果），不是已验证的原生HTTP请求边界。窗口外、单响应内部及被截去部分仍属原全集范围，不删真值；信息不足不能作为已证明正常。

固定小样本与预算见[本轮方案](four-round-prefix-plan.json)：两个四轮窗口、八个既有候选，最多16窗口／48成对判断；结果闭合后单独报告，不扩大为156组全集或实时守卫验收。

### 每轮1KiB输入修订

用户追加批准每轮缩减到1KiB以内，继续暂缓摘要。可复用准备器按实际compact JSON UTF-8字节数限制每轮≤1024，包含结构与截断标记；每个文本字段先取最多300字节的合法UTF-8前缀，若全轮超限则缩减所有文本字段的共同预算。保留原事件顺序、角色、完整工具名称、非空退出码，参数／结果前缀及缺结果／截断标志。去掉JSON缩进、false截断标志、空退出码，已有实际结果时不重复输出存在标志；不依内容关键词筛选，不调用agent或摘要模型挑选信息。操作元数据自身超过预算时明确拒绝，不通过静默丢工具满足限额。

全235现存会话、2514个非压缩／中断边界行为单位的容量调查全部≤1024字节，中位数729；1856个未跨边界四轮窗口，数据包装最大4111字节。这个样本量仅是无推理容量核对；不是2514个模型测试。规则与工程基础指令在窗口前另计，当前合计3081字符；“每轮1KiB”不等于整个请求1KiB。

## Strata判别路线的默认复用方式

用户提出：CPU-only小模型路线确实无法满足需求时，可以使用正在承担任务的Strata模型判断当前轮是否无进展地重复前三轮，输出三个概率。用户随后确认，默认按已经实际验证的原生自动审批／guardian思路处理；先核对并复用现有调用链，只有发现实际场景差异时才设计其他办法。CPU路线的资源约束不自动变成此备选必须额外运行独立CPU模型；允许复用已有Strata推理资源，但不据此自动启用新组。

已核对的基础：[调用方接入](../../docs/codex.md#权限与审批)与[历史审批实测](../../reports/v0.1.38/safety-20261004/approval-mcp.md)证明原生guardian可使用本地qwen_strata所加载量化；测量接入由`tools/reviewer/arw_measure.py`的`local_review_catalog`设置`auto_review_model_override`路由。该证据只证明模型／服务复用和原生审批调用，不证明重复判别已实现、三个概率已可输出，或接口支持任意任务替换。

下一步先追踪触发、历史材料构造、上下文管理、请求调度、结果返回／解析和主任务接续，按真实机制确定输入和缓存方式。此前讨论的独立判别上下文、主会话临时请求分支及额外缓存配置均是待验证候选，不能先选作默认。若原生审批接口只接受审批任务或其输入不满足重复判断，应先列明具体限制及源码／运行证据，再给最小适配方案；不复用风险裁决含义，不改变真实自动审批策略或配置。

重复判别仍需自己的任务说明、三个概率合同、准确性与资源验证；不把原审批成功或历史耗时当作新判断验收。保持原循环／正常真值、规则批次审核和联合F1＝1门槛，具体Strata模型测量先交范围和预算审核。当前没有新增推理、部署、独占操作或默认检测器切换。
