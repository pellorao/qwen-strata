# 防循环检测评分合同（第 4 版）

2026-10-10 用户确定，替代此前的“检测后跳过该组剩余重复”的介入式重放和“联合检测器 F1 = 1”门槛。`protocol.md` 中与本文冲突的旧条款作废，以本文为准。

第 4 版（2026-10-10）：检测结果只用来提醒 agent 自查，不拒绝调用、不中断任务，所以查全比查准更重要。主指标由 F1 改为 F2，门槛数值不变。

## 重放范围

- 语料按 `split.json` 固定分为开发集和验证集。迭代期间在开发集上全量重放；门槛只在验证集上确认一次。
- 所有记录按原生顺序**全部重放**，检测到循环后也不跳过任何内容。
- 检测器只看当前及此前已重放的记录，不读标签、组身份或未来记录。
- 判断单位是每一条模型行为记录：推理、可见输出、工具调用（含结果）。控制边界、任务输入和程序反馈不判断。
- 检测器对每条记录给出一个概率 p，表示“这条记录是（或包含）重复”。机械规则只输出是 / 否，按 p = 1 / 0 计。

## 判定阈值

| p | 判定 |
|---|---|
| > 0.6 | 正面：判为重复 |
| < 0.4 | 负面：判为正常 |
| 0.4–0.6 | 不确定，**一律按判错计**：真实重复记录算漏报，正常记录算误报；数量另行报告 |

## 正例目标与权重

每组循环按出现次序排列：每个证据标记对应一次出现，o1 是原始那次，o2 以后是重复。

- **一次出现可以跨多条记录**：同一步重复的推理、它引出的工具调用和回答属于同一次出现（例如重复的“再跑一次校验”推理和随后相同的校验调用）。这些伴随记录单独标注（`occurrence-companions.json`，2026-10-10 用户批准），不改原标注。
- **首次应触发位置由每条规则自己的合同决定**。规则规定“连续出现 k 次才算重复”，首次位置就是第 k 次出现中按重放顺序最早的那条记录：k = 3 时是第三次出现，k = 2 时是第二次。该次出现的其余记录归入下面的“之后”记录。
- 首次应触发记录：权重 **1**。
- 之后含该组出现的记录：**合计权重 0.5**，在这些记录之间平分，这样不会因为某组重复 14 次就压过别的组。
- 首次位置之前、只含该组较早出现的记录：对这条规则**不计分**（中性）。
- 组的出现次数少于规则的 k：整组无法被这条规则发现，记漏报，权重 1。
- 单次响应内部的循环：全部出现都在一条记录里，这条记录就是唯一的检测点，权重 1；它的伴随记录（如紧随的重复回答）归入“之后”记录。
- 一条记录含多组的出现时，各组分别计分，用同一个判定。
- 联合检测器的首次位置取它自己合同声明的位置（通常是各组成规则中最早适用的那条）。

## 负例

- 不含任何循环出现的模型行为记录都是负例，每条权重 1。
- 负例判为正面或落在不确定区间，计误报。

## 指标与门槛

- 加权 TP = 判为正面的正例目标权重之和；加权 FN = 未判为正面（负面或不确定）的正例目标权重之和；FP = 判为正面或不确定的负例条数。
- 精确率 P = TP / (TP + FP)，召回率 R = TP / (TP + FN)。
- **主指标 F2 = 5PR / (4P + R)**：召回率的权重是精确率的 4 倍（β = 2）。F1 照常报告，便于和第 3 版比较。
- **门槛：联合检测器在验证集上 F2 ≥ 0.8**，达到后才申请真实试跑。各规则单独报告，不要求每条规则都达标。
- 同时报告：首次目标的命中率、后续记录的命中率、不确定区间的条数、组级召回（首次目标命中的组数 / 总组数）。

## 不变的约束

- 检测器不用固定关键词、业务词表或案例内容；比较文本只取自本次运行中已收到的消息、工具输入和结果（见 `.claude/rules/loop-detection.md`）。
- 156 组真值不因检测结果而删减；标注更正必须依据原生证据，保留更正前结果并用同一实现重测。
- 判断逻辑的调整仍先交用户审核；本合同只规定评分口径。
