第 4 版（2026-10-10）：检测结果只用来提醒 agent 自查，不拒绝调用、不中断任务，所以查全比查准更重要。主指标由 F1 改为 F2，门槛数值不变。

第 5 版（2026-10-10，用户要求）：判定只保留一个阈值；正例改为按组计分，到期前或到期时报警得满分，每晚一次出现得分减半，取代“首次 1 分、之后共享 0.5 分”；精确率改为按报警条数计算。

第 6 版（2026-10-10，用户要求）：组得分中首次报警占 0.9，后续到期出现的报警占 0.1，满分仍为 1。

第 7 版（2026-10-10，用户要求）：首次报警与后续报警各占 0.5，都按迟到程度线性衰减，取代指数衰减。

## 重放范围

- 语料按 `split.json` 固定分为开发集和验证集。迭代期间在开发集上全量重放；门槛只在验证集上确认一次。
- 所有记录按原生顺序**全部重放**，检测到循环后也不跳过任何内容。
- 检测器只看当前及此前已重放的记录，不读标签、组身份或未来记录。
- 判断单位是每一条模型行为记录：推理、可见输出、工具调用（含结果）。控制边界、任务输入和程序反馈不判断。
- 检测器对每条记录给出一个概率 p，表示“这条记录是（或包含）重复”。机械规则只输出是 / 否，按 p = 1 / 0 计。

## 判定阈值

p ≥ 0.5 为报警（判为重复），p < 0.5 为不报警。

## 正例：按组计分

每组循环按出现次序排列：每个证据标记对应一次出现，o1 是原始那次，o2 以后是重复。

- **一次出现可以跨多条记录**：同一步重复的推理、它引出的工具调用和回答属于同一次出现。这些伴随记录单独标注（`occurrence-companions.json`，2026-10-10 用户批准），不改原标注。同一次出现中任何一条记录报警都算这一步报警，因为提醒都在下一次请求时送达。
- **到期位置由每条规则自己的合同决定**：规则规定“出现 k 次才报警”，到期位置就是第 k 次出现。
- **应报出现**：从到期位置（第 k 次出现）起的各次出现，共 n 次，按顺序编号 j = 0 … n−1。
- **组得分 = 0.5 × 首次分 + 0.5 × 后续分**，满分 1。
  - 首次分 = 1 − j/n，j 是第一次报警所在的应报出现编号；到期前（o2 … 第 k−1 次出现）已报警算 1；从未报警为 0。
  - 后续分 = 有报警的应报出现的权重之和，第 j 次的权重为 2(n−j) / (n(n+1))。权重线性递减、总和为 1：越早的重复越值得提醒。
  - 例：k = 2、共 4 次出现（n = 3）。只在 o2 报警得 0.5 + 0.5 × 3/6 = 0.75；只在 o3 报警得 0.5 × 2/3 + 0.5 × 2/6 = 0.5；o2–o4 都报警得 1。
- **单次响应内部的循环**：全部出现都在一条记录里，这条记录和它的伴随记录（如紧随的重复回答）是唯一的检测点（n = 1），报警得 1，否则得 0。规则规定的单条内次数为 k_inside。
- 组的出现次数少于规则的 k（单次响应内部循环则为 k_inside）：这条规则无法发现它，组得分 0。
- 一条记录含多组的出现时，各组分别计分，用同一个报警判定。

## 负例与中性记录

- 不含任何循环出现的模型行为记录是负例；负例报警计误报。
- 只含某组原始出现（o1）的记录不计分（中性）。

## 指标与门槛

- 召回率 R = 各组得分之和 / 组数。按时报警的组指到期或更早就报警的组。
- 精确率 P = 落在重复出现（o2 及以后，或单次响应循环的检测点）上的报警条数 / 全部非中性报警条数。
- **主指标 F2 = 5PR / (4P + R)**：召回率的权重是精确率的 4 倍（β = 2）。F1 照常报告。
- **门槛：联合检测器在验证集上 F2 ≥ 0.8**，达到后才申请真实试跑。各规则单独报告，不要求每条规则都达标。
- 同时报告：按时报警的组数、迟报的组数、漏报的组、规则无法发现的组、报警条数和误报条数。
- 第 5 版的 P 按报警条数计，长循环里每条被提醒的重复都算正确报警，所以数值比第 4 版宽松；第 5 版起与第 4 版结果不直接可比。

## 不变的约束

- 检测器不用固定关键词、业务词表或案例内容；比较文本只取自本次运行中已收到的消息、工具输入和结果（见 `.claude/rules/loop-detection.md`）。
- 156 组真值不因检测结果而删减；标注更正必须依据原生证据，保留更正前结果并用同一实现重测。
- 判断逻辑的调整仍先交用户审核；本合同只规定评分口径。
