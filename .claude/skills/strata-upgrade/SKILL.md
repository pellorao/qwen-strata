# Strata 升级后流程

目标总耗时 15–30 分钟，包括准备、运行、核查和报告。

1. **核查发布说明**：阅读实际安装版本的 GitHub 官方 Release，以及从上一基线到该版本之间的相关发布记录，必要时跟进其中的 PR 和 Issue。重点看推理性能、上下文和压缩、工具调用、搜索、Responses / Messages 兼容、计量和参数。逐条写清：带来什么收益或问题、能否直接用现有配置启用、还需要什么验证。
2. **核对安装**：版本和提交、文件 SHA、当前配置、基础提示文件。
3. **短调用链检查**（需要先用 `/model-run-proposal` 获批）：一个实例，每项跑一次，覆盖生成、工具调用、MCP、搜索、短压缩和同线程恢复。不取均值，也不算正式评分。
4. **报告**：写入 `reports/<版本>/upgrade.md`，内容包括发布说明结论、当前配置、通过项、失败项和未验证项。结论只标"通过短检查"，不继承旧版本的完整验收结论。
5. **异常处理**：先安全收尾，再提出保留旧版、回退或另行调查的选项。不自动扩大调查范围。

较完整的回归（故障和取消恢复、审批质量、Reviewer 兼容）按周集中安排，参数比较只在出现相关变化或性能退化时进行，二者都需要单独申请。
