# 防循环检测规则

语料：两台机器全部历史会话，235 个会话 / 5303 条模型行为，确认 156 组循环。见 `benchmarks/loop-detection-v2/protocol.md`。

## 检测器约束
- 不用固定关键词、业务词表或案例内容判断重复。比较的文本只能动态取自本次运行中已经收到的消息、工具输入和结果；算法、结构解析和数值阈值可以固定。
- 检测器不读取标签或冻结答案，也不把历史审核答案反馈给模型。
- 调用方说"继续"不豁免重复：模型返回相同结果、没有新的验证、交付或实质进展，就算重复。
- 排除以下正常情况：不同要求的正常映射、一次合理复核、真实修复、输入变化、镜像和压缩事件。
- 仅凭动态文本匹配无法覆盖已确认的语义重复时，先向用户说明证据和限制，不暗中加回关键词、删除正例或放宽门槛。

## 计数与评分
评分合同见 `benchmarks/loop-detection-v2/scoring-contract.md`（2026-10-10 第 3 版），要点：
- 全部记录按顺序重放，检测到循环后不跳过。每条模型行为记录给一个概率：> 0.6 判重复，< 0.4 判正常，0.4–0.6 一律按判错计。
- 正例目标按每条规则自己的首次应触发位置（如“连续 k 次”规则的第 k 次出现）：首次记录权重 1，之后的记录合计 0.5 平分；首次之前的出现不计分。单次响应内部循环在唯一检测点判断，权重 1。
- **联合检测器加权 F1 ≥ 0.8 是真实试跑的门槛**；各规则单独报告，不要求每条都达标。
- 逐次找出全部可确认的循环组，分别记录组数和总次数。无法确认的候选单列。

## 流程
- 每次调整判断逻辑（阈值、匹配、重置、优先级）之前，先交用户审核。获批后完成该批的实现、测试、复核和标签更正重测，然后停下。
- 当前评估三条路线，分别出结果，不混合：Strata 自判别（复用原生 auto_review / guardian 机制）、纯程序机械判断、两者组合。CPU 小模型路线已经关闭。
- 离线全集联合 F1 ≥ 0.8 后，才申请一次真实试跑。试跑结果报告审核后，由用户决定是否完成三次。
