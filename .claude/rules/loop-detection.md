# 防循环检测规则

语料：两台机器全部历史会话，235 个会话 / 5303 条模型行为，确认 156 组循环。见 `benchmarks/loop-detection-v2/protocol.md`。

## 检测器约束
- 不用固定关键词、业务词表或案例内容判断重复。比较的文本只能动态取自本次运行中已经收到的消息、工具输入和结果；算法、结构解析和数值阈值可以固定。
- 检测器不读取标签或冻结答案，也不把历史审核答案反馈给模型。
- 调用方说"继续"不豁免重复：模型返回相同结果、没有新的验证、交付或实质进展，就算重复。
- 排除以下正常情况：不同要求的正常映射、一次合理复核、真实修复、输入变化、镜像和压缩事件。
- 仅凭动态文本匹配无法覆盖已确认的语义重复时，先向用户说明证据和限制，不暗中加回关键词、删除正例或放宽门槛。

## 计数与评分
评分合同见 `benchmarks/loop-detection-v2/scoring-contract.md`（2026-10-10 第 7 版），要点：
- 全部记录按顺序重放，检测到循环后不跳过。每条模型行为记录给一个概率，p ≥ 0.5 为报警。
- 正例按组计分：规则规定第 k 次出现报警，首次报警和后续报警各占 0.5，都按迟到程度线性衰减，满分 1；一次出现可跨同一步的推理、调用和回答。单次响应内部循环在唯一检测点判断。召回率是组得分的平均，精确率按报警条数计。
- **联合检测器 F2 ≥ 0.8 是真实试跑的门槛**（只发提醒，查全优先；F1 照常报告）；各规则单独报告，不要求每条都达标。
- 逐次找出全部可确认的循环组，分别记录组数和总次数。无法确认的候选单列。

## 开发集与验证集
- `benchmarks/loop-detection-v2/split.json` 由 `tools/loop/make_split.py` 生成。2026-10-10 第一次划分（种子 11994）的验证集门槛未通过，按用户要求全部重新随机划分（种子 33688）：开发集 165 个会话 / 117 组，验证集 70 个会话 / 39 组；共享同一初始任务的会话总在同一侧。
- 迭代只用开发集：重放、抽样、误判分析和标签复查都限于开发集。验证集在门槛确认之前不读取、不抽样、不复查、不重放。
- 门槛确认在验证集上进行一次；确认后不再按验证集结果改规则。如需再迭代，另行商定新的验证方式。

## 流程
- **迭代授权**（用户 2026-10-10）：迭代期间，阈值、匹配、提示词、重置、优先级等判断逻辑调整由 Main 直接修改和测试，不逐次送审；每轮的改动、结果和误报写入轮次记录。模型运行授权覆盖整个迭代直到门槛确认。检测器约束、标注更正流程和门槛不因此放宽。
- 每轮：机械规则在开发集全量重放（不调用模型，几秒）。
- 停止点：开发集联合 F2 ≥ 0.8 后做验证集门槛确认；或连续 5 轮没有改善。到达后停下汇报。
- **只用机械规则**（用户 2026-10-10）：不用模型判断重复。CPU 小模型和 Strata 判断两条路线都已关闭，见[关闭报告](../../reports/v0.1.41/loop-strata-judge/summary.md)。
- **介入方式只发提醒**：检测到重复后，提醒 agent 检查当前工作是否陷入无进展的循环，不拒绝调用，也不中断任务。
- 验证集联合 F2 ≥ 0.8 后，才申请一次真实试跑。试跑结果报告审核后，由用户决定是否完成三次。
